# 베스페라 호텔

서로를 경계하는 판타지 종족의 손님을 받아, 각자의 숙박 조건과 관계를 읽고 제한된 객실에 배치하는 2D 호텔 경영 퍼즐입니다.

플레이어는 유산으로 물려받은 낡은 베스페라 호텔의 인간 지배인이 됩니다. 누구를 손님으로 받을지 결정하고, 모두가 머물 수 있는 배치를 찾고, 더 나은 경험을 만든 대가로 호텔을 성장시켜야 합니다. 한 종족에 특화된 안전한 호텔을 만들 수도 있고, 충돌하는 여러 종족을 함께 받아 더 어렵고 가치 있는 화합을 추구할 수도 있습니다.

> 필수 조건을 지키는 것은 좋은 서비스가 아니라 영업이 가능한 최소선입니다. 평판은 무난한 숙박이 아니라 기대를 넘거나 저버린 경험에서 변합니다.

## 게임 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 장르 | 조건 최적화 배치 퍼즐 + 로그라이크 호텔 경영 |
| 핵심 조작 | 마우스 중심 2D 드래그 앤 드롭 |
| 핵심 판단 | 손님 수용·거절, 객실 배치, 시설 투자, 종족 관계와 장기 경로 선택 |
| 세계관 | 인간 지배인이 경영하고 중립 오토마타가 접객 실무를 맡는 다종족 호텔 |
| 주요 모드 | 시나리오 캠페인, 무한 영업 |
| 현재 공개 빌드 | 튜토리얼과 5회의 `개장 전 초청 영업`을 담은 v2 쇼케이스 |

내부적으로는 제약 충족 문제(CSP)의 구조를 사용하지만 전문 용어를 플레이 전면에 내세우지는 않습니다. 플레이어는 `필수 숙박 조건`, `개인 선호`, `미열람 규칙`, `숨은 선호`, `종족 시너지`를 읽고 자연스럽게 가능한 답과 더 좋은 답을 구분하게 됩니다.

## 한 번의 영업

1. 예약 신청에서 손님의 종족·등급·숙박 일수와 공개 조건을 확인합니다.
2. 제한된 응대 인원과 실제 객실 여유를 비교해 손님을 수용하거나 거절합니다.
3. 제한 시간 안에 손님을 객실로 드래그해 모든 필수 조건을 만족시킵니다.
4. 여러 유효 배치 중 개인 선호, 종족 시너지와 상극을 비교해 더 좋은 답을 찾습니다.
5. 결산에서 손님별 정성 후기를 읽고 만족·평판 변화의 원인을 확인합니다.
6. 수입을 증축, 시설, 인테리어와 객실 정비에 투자해 다음 영업의 문제 자체를 바꿉니다.

처음 놓은 손님은 무료로 배치할 수 있지만 이동·교환·회수에는 시간이 듭니다. 마감까지 직접 해결하지 못하면 오토마타가 필수 조건을 만족하는 배치를 찾되 선호를 최적화하지는 않습니다. 유효 배치가 불가능하면 필요한 예약을 취소하고 호텔이 손실을 부담합니다.

## 만족도와 평판의 원칙

베스페라의 평판은 현실적인 인과를 따라야 합니다.

- 모든 필수 조건을 지킨 숙박은 기본적으로 평판 `0`입니다. 문제없이 묵었다는 이유만으로 평판이 자동 상승하지 않습니다.
- 추가 선호와 좋은 종족 조합, 적절한 시설은 만족을 높입니다. 공개되거나 기대치에 의해 활성화된 불호는 만족을 낮춥니다.
- 낮은 등급의 손님은 조건이 적고 한 번의 후기가 평판에 미치는 영향도 작습니다.
- 높은 등급의 손님은 더 많은 선호·불호와 높은 기대치를 가지며, 만족과 불만이 평판에 더 크게 반영됩니다.
- 호텔의 격이 손님 등급보다 충분히 높으면 낮은 등급 손님은 사소한 불호를 관용하고 좋은 호텔에 머문 경험 자체를 긍정적으로 받아들일 수 있습니다.
- 정확한 만족도 숫자는 플레이어에게 노출하지 않습니다. 결산의 `호평 / 무난 / 아쉬움` 후기와 원인 문구로 다음 배치를 학습하게 합니다.

일반적인 접객 태도나 직원 차별은 별도 운영 변수가 아닙니다. 인간 지배인이 운영 방향과 최종 판단을 맡고, 생물 종족의 혈통·신앙·생존 이해관계에서 벗어난 오토마타 인공 종족이 그 지시 아래 같은 규정으로 접객·시설 실무를 수행합니다. 만족과 평판은 객실, 시설, 선호·불호, 종족 관계와 호텔의 격에서 발생합니다.

## 베스페라와 다섯 종족

베스페라는 서로 갈등하는 종족도 중립 협약 아래 안심하고 머물 수 있는 드문 장소입니다. 그 신뢰의 중심에는 감정이나 종족 이해관계로 손님을 차별하지 않는 오토마타 운영진이 있습니다.

정식 캠페인의 1차 우호·중립 투숙 종족은 다음 다섯 종족입니다.

1. 인족
2. 뱀파이어
3. 늑대인간
4. 마녀
5. 몽마

오토마타는 여섯 번째 일반 투숙 종족이 아니라 호텔의 중립 운영을 맡는 별도의 인공 종족입니다. 각 개체는 이름·성격·기억과 판단을 가진 인격체이며, 남성형·여성형은 생물학적 성별이 아니라 외형적 표현입니다. 이들은 오래전부터 베스페라의 중립 규약을 이어 왔습니다.

종족은 단순한 속성 묶음이 아닙니다. 자연 출생과 전환 출신의 갈등, 오래된 박해와 불신, 집단마다 다른 생활 방식이 숙박 조건·시설·시너지와 시나리오 선택으로 이어집니다. 같은 종족을 모으는 것이 항상 정답도, 여러 종족을 섞는 것이 항상 선한 선택도 아닙니다. 전문화는 안정적인 해법을 제공하고, 화합은 더 복잡한 제약을 감수한 만큼 높은 보상과 새로운 경로를 엽니다.

현재 공개 v2는 빌드 호환을 위해 4종족 16명의 손님, `N/R/SR/SSR` 등급과 수인 명칭을 유지합니다. 정식판에서는 `UR`을 포함한 `N/R/SR/SSR/UR` 구조로 확장하고, 수인의 원형을 늑대인간으로 전환합니다. 몽마 손님은 다른 종족의 투숙 기반이 형성된 중·후반에만 의미가 있으므로 최소 `SR`부터 등장합니다. 몽마의 등급이 높아질수록 같은 영업에 머무는 타종족 손님 수를 더 많이 요구하는 선호를 가집니다. 구체적인 종족 설정은 [종족과 시너지 시스템](docs/25_SPECIES_AND_SYNERGY_SYSTEM.md)에 정리되어 있습니다.

## 시나리오 캠페인

플레이어는 인간 지배인으로서 정해진 기한 안에 상속 조건과 호텔의 운영 목표를 해결해야 합니다. 캠페인의 하루는 비서 오토마타와 예약·객실 장부를 확인하는 아침 브리핑으로 시작하고, 영업 뒤 마감 보고로 끝납니다. 반복되는 장부와 대화는 다음 영업을 준비하는 기능인 동시에 호텔과 인물들의 이야기를 보여주는 시나리오 장면입니다.

캠페인은 다섯 챕터의 공통 흐름을 바탕으로 다음 선택을 누적합니다.

- 어떤 종족의 손님과 협약을 우선할 것인가
- 한 종족에 특화할 것인가, 일부를 중재할 것인가, 어려운 화합을 시도할 것인가
- 제한된 자금을 당장의 안전과 장기 성장 중 어디에 투자할 것인가
- 관계 인물과 어떤 사건을 해결하고 어떤 관계를 쌓을 것인가
- 호텔의 장기적인 방향을 어디로 이끌 것인가

현재 회색 상자 캠페인은 `새 게임 → 프롤로그 → 아침 브리핑 → 예약·배치·결산 → 챕터 장면 → 결말 → 후일담 → 실행 기록`의 기능적 뼈대를 실제로 통과합니다. 세부 사건과 최종 수치는 아직 대역 데이터지만 서로 다른 여섯 종류의 결말을 판정할 수 있습니다. 세부 명칭과 도달 조건은 게임 안에서 확인할 수 있습니다.

챕터의 첫 실패가 반드시 즉시 게임 오버로 이어지지는 않습니다. 회복 영업, 추가 채무나 기회 손실을 통해 운영을 되돌릴 여지를 둡니다. 상세 임계치와 경제 수치는 이후 시뮬레이션으로 확정합니다.

## 관계 인물

각 우호·중립 종족에는 캠페인의 중심 관계 인물이 한 명씩 존재합니다. 이들은 호텔에 고용되기 위해 기다리는 직원이 아니라 호텔 밖에 자기 삶과 공동체가 있는 손님으로 처음 등장합니다.

관계는 `첫 방문 손님 → 단골 손님 → 종족 연락책 → 조사·운영 협력자 → 선택적 상주 동반자`로 발전할 수 있습니다. 협력자가 된 뒤에도 일상 접객은 오토마타가 담당합니다. 관계 인물은 종족 정보, 협약, 사건 대응, 조사, 전시품 후보와 특수 선택지를 통해 운영을 돕습니다.

- 조사 신뢰는 여러 인물과 함께 높일 수 있고 공동 문제 해결에 사용합니다.
- 개인 호감도는 제한된 자유시간과 개인 장면에 사용합니다.
- 관계 인물은 N/R/SR/SSR 등급이나 직접적인 금액 보상으로 평가하지 않습니다.
- 후일담에는 실제로 만났거나 관계를 맺은 인물만 등장합니다.
- 운영 결과가 좋지 않더라도 모든 인물의 삶이 일괄적으로 무너지지는 않습니다. 호텔에 실제로 의존했던 계획과 관계만 그 인과에 따라 달라집니다.

새 게임에서는 플레이어 성별, 비서 오토마타의 외형, 관계 인물의 성별 구성을 각각 정할 수 있습니다. 이는 이름·외형·호칭과 일부 개인 장면의 표현을 바꾸며, 기본 운영 능력치나 관계 가능 여부에 자동 보정은 주지 않습니다. 정식판의 일반 손님도 성별 정보를 가질 수 있고, 설정상 인과가 있는 개별 선호·불호와 사건만 이를 선택적으로 참조합니다. 성별만으로 모든 손님에게 공통 보너스나 페널티를 주지는 않으며, 세계관상 여성만 존재하는 마녀 관계 인물은 여성으로 고정됩니다.

## 무한 영업과 전시품

무한 영업은 캠페인을 그대로 반복하는 모드가 아니라 예약·배치·정산·공사 판단을 무작위 시드와 장기 빌드로 확장한 생존 운영입니다. 일정 영업마다 다음 평판 감사 목표가 미리 공개되고, 통과할수록 새로운 손님·시설·계약과 더 큰 위험이 열립니다. 목표에 미달하면 호텔이 폐업하며 해당 런의 기록을 남깁니다.

전시품은 별도 객실에 배치하는 가구가 아니라 현재 런에 지속되는 패시브입니다. 호텔 평판은 공용 후보군을, 종족 우호도와 관계 인물의 조사 신뢰·개인 호감도는 각 출처의 전용 후보군을 엽니다. 플레이어는 무작위 후보 중 하나를 선택해 빌드를 만들고, 제안·획득·발동 기록을 운영 수첩의 도감에 남깁니다.

운영 수첩은 캠페인과 무한 영업이 공유하는 영구 지식입니다. 발견한 숙박 규칙, 손님, 시설, 시너지와 전시품 도감은 남지만 골드, 평판, 시설 소유, 관계 수치와 현재 패시브 조합은 각 런에 따로 보존됩니다.

2. 코어 플레이테스트의 평가 난도와 초청 정책 결정, 신규 플레이어 검증
3. 최종 운영 목표와 무한 영업 감사 경제 시뮬레이션
4. 종족·시너지·관계 장면을 교체 가능한 외부 콘텐츠 규격으로 검증
5. 대표 경로 자동 회귀와 콘텐츠 누락·엔딩 도달 가능성 검산 강화
6. 기능적 뼈대 통과 뒤 아트·UX·오디오와 도트 캐릭터 자산 확장

## 플레이와 실행

현재 동결된 v2는 별도 설치 없이 플레이할 수 있습니다.

<https://kahadra.github.io/vespera-hotel-prototype/>

소스에서 실행하려면 저장소 루트에서 정적 서버를 시작합니다.

```powershell
python -m http.server 8765
```

- 공개 쇼케이스: <http://127.0.0.1:8765/>
- 회색 상자 캠페인: <http://127.0.0.1:8765/?mode=campaign>

로컬 파일 주소로 직접 열면 JavaScript 모듈과 JSON 접근이 차단될 수 있습니다. 게임 실행 자체에는 외부 패키지가 필요 없으며, 브라우저 자동 검증을 새 환경에서 실행할 때만 `pip install -r requirements-dev.txt`가 필요합니다.

```powershell
python .\tools\validate_prototype_puzzles.py
python .\tools\test_timed_service.py
python .\tools\test_campaign_spine.py
python .\tools\smoke_browser.py --facility SECRET_PASSAGE
```
