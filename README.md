# 베스페라 호텔

서로 다른 종족의 숙박 조건과 관계를 읽고, 제한된 객실에 손님을 배치하는 CSP 기반 판타지 호텔 경영 게임입니다. 현재는 핵심 루프를 검증하는 `v2` 웹 빌드를 플레이할 수 있으며, 다음 단계에서는 상속받은 호텔을 정식 명소로 성장시키는 캠페인과 종족·시너지·관계 시스템을 확장합니다.

## 프로젝트 상태

| 구분 | 상태 | 범위 |
| --- | --- | --- |
| v2 웹 빌드 | `COMPLETE` | 튜토리얼, 5회의 개장 전 초청 영업, 객실 배정·운영·성장 루프 |
| 코어 플레이테스트 | `NEXT` | 신규 플레이어 테스트, 가독성·판단 밀도·반복 재미 검증 |
| 정식 캠페인 | `PROPOSED` | 5개 챕터·최소 50스테이지, 최종 운영 목표, 엔딩과 엔드리스 |
| 종족·시너지 시스템 | `DRAFT` | 우호·중립 5종과 적대 종족 도플갱어, 직업·신앙·분기형 시너지 |

정식 캠페인, 히로인 관계선, 도감·업적, 도플갱어 침투는 설계 단계이며 현재 v2 빌드에 구현된 기능이 아닙니다. 현재 동작과 확장 기획의 상세 경계는 [세로 단면 명세](docs/03_VERTICAL_SLICE_SPEC.md)와 [제작 로드맵](docs/02_PRODUCTION_ROADMAP.md)을 기준으로 합니다.

## 현재 플레이 가능한 v2

### 핵심 플레이 흐름

1. 예약 신청에서 손님의 종족·등급·숙박 조건을 확인하고 수용 또는 거절합니다.
2. 제한 시간 안에 손님을 객실로 드래그해 필수 조건을 모두 만족시킵니다.
3. 선호, 종족 시너지와 상극을 비교해 여러 가능한 배치 중 더 좋은 답을 찾습니다.
4. 결산에서 숨은 선호를 발견하고 수익과 평판을 얻습니다.
5. 증축·시설·인테리어·정비에 투자해 다음 영업의 조건을 바꿉니다.

### 구현된 범위

- N/R/SR/SSR 등급, 4종족 16명 손님, 시드 기반 예약·공사 제안
- 손님 수용·거절, 2분 체크인, 드래그 전용 배정·교환·해제
- 필수 숙박 조건, 공개 선호, 미열람 규칙, 결산 뒤 발견하는 숨은 선호
- 종족 인원 시너지와 상극, 재배치 시간 비용, 긴급 배정과 취소 손실
- 1박·연박, 연박 객실 고정, 재방문 만족 보너스
- 객실 청결·내구도 마모, 유료 정비, 응대 한도와 실제 객실 여유의 분리
- 누적 시설·인테리어와 `F1-D → F2-D → F3-D` 순차 증축
- 시간 제한 없는 튜토리얼과 5회의 개장 전 초청 영업

현재 5회 구성은 짧은 시연 안에서 성장 층위를 검증하기 위해 해금을 압축한 것이며 정식판의 성장 속도를 뜻하지 않습니다.

## 정식 캠페인 방향

플레이어는 유산으로 물려받은 낡은 베스페라 호텔을 운영합니다. 베스페라는 서로 갈등하는 종족도 중립 협약 아래 안전하게 머물 수 있는 드문 장소이며, 플레이어는 정해진 영업 기한 안에 목표 금액 또는 채무 상환 조건을 달성해 호텔을 지켜야 합니다.

- 1차 제작 목표: 5개 챕터, 총 50스테이지
- 확장 범위: 반복 피로와 제작 비용 검증 뒤 100~200스테이지
- 최종 목표: 제한된 영업 횟수 안에 명시된 금액·운영 조건 달성
- 엔딩 이후: 조합과 조건이 계속 변하는 엔드리스 영업
- 챕터 역할: 규칙 학습 → 종족 갈등과 전문화 → 관계 분기 → 침투 위기 → 최종 운영·관계 결산

구체적인 사건과 대사는 나중에 외부 콘텐츠로 붙일 수 있도록, 현재 문서에서는 세계관의 원인과 시스템에 필요한 사건 역할만 고정합니다.

## 종족·직업·시너지 설계

정식판에서는 종족과 직업을 분리합니다. 성기사는 인족 교단의 직업이며, 다른 종족도 각 문화와 신앙에 맞는 고유 직업 풀을 가집니다. 마녀는 선천 종족과 후천 수련·소속 경로를 함께 허용하고, 수인은 개과·고양이과처럼 계통별 인원 성향을 나눕니다.

1차 종족 명단은 다음 여섯 종족을 기준으로 합니다.

1. 인족
2. 뱀파이어
3. 수인
4. 선천 마녀
5. 야마 후보 — 서큐버스·인큐버스 등 꿈과 밤의 마귀 계통
6. 도플갱어 — 외신·악신의 분신 단말인 적대 종족

앞의 다섯 종족은 우호·중립 투숙객이며, 도플갱어는 정상 예약 풀에 들어오는 여섯 번째 우호 종족이 아닙니다. 따라서 일반 종족 시너지와 표준 히로인 관계선은 다섯 투숙 종족을 기준으로 하고, 도플갱어는 별도의 침투·보안·사보타지 규칙으로 다룹니다.

시너지는 모든 종족에게 같은 2명·3명 보너스를 주지 않습니다.

- 집단 인원 곡선: 개과 수인은 모일수록 결집하지만 고양이과 수인은 과밀을 싫어하는 식으로 계통별 곡선을 사용
- 다종 시너지: 2종·3종·4종 이상의 혼합 투숙에 보상과 운영 부담을 함께 부여
- 지정 조합: 종족·계통 조합과 직업·신앙 조합을 구분해 좋은 시너지와 나쁜 시너지를 설계
- 시나리오 반전: 선택 결과에 따라 같은 조합이 강화·악화되거나 버프와 디버프가 서로 반전
- 발견형 규칙: 종족 시나리오가 쌓이면 새로운 선호·상극·시설 대응법을 공개

## 히로인·도감·업적

- 우호·중립 투숙 종족 5종에 대응하는 표준 히로인 5명을 1차 기준으로 둡니다.
- 히로인은 N/R/SR/SSR 등급과 금액 보상에서 분리하고, 호감도·열람 장면·최종 선택만 핵심 상태로 사용합니다.
- 제한된 사건 기회 때문에 한 번의 런에서 모든 관계를 완성할 수 없게 합니다.
- 일반 손님은 만남, 숙박, 숨은 선호와 대표 기록을 도감에 남기며 이후 도트 캐릭터 수집으로 확장합니다.
- 업적은 특이한 시너지, 고난도 운영, 발견, 관계 엔딩과 엔드리스 기록을 수집하게 합니다.

## 도플갱어 침투

도플갱어는 여섯 번째 종족이자 중·후반부의 중심 적대자입니다. 원래 예약 손님의 도착을 방해하고 예약 증서를 탈취한 뒤 다른 종족으로 위장해 체크인하며, 시설 파손·명부 변조·평판 사보타지의 책임을 모방한 종족에 돌립니다.

- 챕터 1~3: 예약 원본 열람은 편의 기능으로 제공하지만 실제 침투는 발생하지 않음
- 챕터 4: 고정 사건으로 예약 원본과 도착 관찰의 비교를 다시 학습하고 침투 위험을 명시
- 단서: 예약 내용과 실제 관찰의 불일치, 이미 발견한 종족 규칙·선호·시너지의 비정상적 미발동
- 대응: 비공개 확인, 공개 지목, 보안 객실 배치, 탐지 시설 설치
- 대가: 정상 손님을 잘못 의심하거나 공개 지목하면 만족도와 종족 평판 페널티 발생
- 공정성: 실제 단말에는 서로 다른 경로의 단서를 최소 두 개 제공하고, 탐지 시설은 범위 안에서 확정 판별

도플갱어의 정체는 새로운 공개 제약 조건으로 추가하되, 이미 만족한 필수 객실 조건의 참·거짓을 나중에 뒤집지는 않습니다. 이 방식으로 기존 CSP 객실 배정 위에 조사와 보안 판단을 더합니다.

## 제작 우선순위

1. v2 신규 플레이어 테스트로 객실 배정과 운영 루프의 재미를 판정
2. 종족·계통·문화·신앙·직업 데이터 구조와 우호·중립 5종의 기본 규칙 확정
3. 5개 챕터·50스테이지의 규칙 도입 순서와 대표 레벨 제작
4. 야마 표본 손님, 히로인 관계 사건, 도플갱어 침투 사건을 각각 한 세트씩 검증
5. 도감·업적·엔딩·엔드리스까지 연결한 콘텐츠 알파 제작
6. 아트·UX·오디오와 도트 캐릭터 자산을 단계적으로 적용

## 공개 플레이

별도 설치 없이 다음 주소에서 현재 v2를 플레이할 수 있습니다.

<https://kahadra.github.io/vespera-hotel-prototype/>

저장소 루트의 `index.html`이 실행되며 Python, 로그인, 별도 서버는 필요하지 않습니다.

## 로컬 실행과 검증

소스에서 직접 실행할 때는 저장소 루트에서 정적 서버를 시작합니다.

```powershell
python -m http.server 8765
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 로컬 파일 주소로 직접 열면 JavaScript 모듈과 JSON 접근이 차단될 수 있습니다.

```powershell
python .\tools\validate_prototype_puzzles.py
python .\tools\test_timed_service.py
python .\tools\smoke_browser.py --facility SECRET_PASSAGE
```

브라우저 자동 검증을 새 환경에서 실행할 때만 `pip install -r requirements-dev.txt`가 필요합니다. 게임 실행 자체에는 외부 패키지가 필요 없습니다.
