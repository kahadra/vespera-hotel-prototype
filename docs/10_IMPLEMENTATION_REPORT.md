# 프로토타입 구현 결과

- 상태: `v2 FIVE-NIGHT FLOW PASS · CAMPAIGN GREYBOX SPINE PASS · ENDLESS GREYBOX SPINE PASS`
- 대상: 정적 웹 프로토타입
- 기준 해상도: 1280×720

## v2 현재 구현 요약

현재 빌드는 시간 제한 없는 객실 배정 연습과 튜토리얼을 제외한 5회 실제 영업으로 구성된다. 5회 안에 성장 구조를 빠르게 보여 주는 심사용 쇼케이스이며 정식 게임의 해금 속도를 뜻하지 않는다.

### 한 세션에서 작동하는 것

1. `개장 전 초청 영업` 초대장과 진행 표식
2. 2인 객실 배정 연습 또는 건너뛰기
3. 120초 실제 영업 5회와 재배치 5초 비용
4. N/R/SR/SSR 태그와 평판·단계·시드 기반 예약 신청
5. 2회차 R, 3회차 SR 보장과 5회차 쇼케이스 전용 SSR 특별 초대
6. 손님 수용·거절, 필수 숙박 조건, 공개 개인 선호, 현재 만족도 계산
7. 종족×등급 숨은 선호의 결산 열람과 재방문 만족 보너스
8. 연박 손님의 첫 객실 고정과 매일 만족도 재평가
9. 객실 청결·내구 마모, 가용 기준, 영업 사이 유료 정비
10. 4종족의 인원 시너지와 지정 상극
11. 누적 시설·인테리어와 `F1-D → F2-D → F3-D` 순차 동관 증축
12. 기본 5명에서 증축 객실당 1명씩 증가하는 예약 응대 한도와 별도 물리 객실 한도
13. 예약 단계에서 연박 고정 위치와 사용 불가·미증축 객실을 확인하는 읽기 전용 객실도
14. 손님별 내부 만족도와 `호평 / 무난 / 아쉬움` 정성 후기, 등급별 평판 영향
15. 각 층 엘리베이터와 바로 인접한 A열 소음 객실의 시각적 연결
16. 마지막 결산 뒤 데이터 기반 종료 판정, 엔딩 ID·핵심 지표와 최근 실행 기록 저장
17. 조작·페이지 이탈 체크포인트와 새로고침 뒤 `지난 영업 이어하기`
18. 시나리오 모드 전용 비서 오토마타 아침·마감 장면, 같은 날 아침 복귀와 숨은 선호 기억 상태 계약

영업 사이에는 `영업 준비 / 공사 계약` 한 화면에서 빈 객실을 정비한다. 공사 제안은 `동관 증축`과 `시설·인테리어`로 나누며 각 분류에서 최대 1건을 계약한 뒤 다음 영업으로 간다. 아무 계약도 하지 않는 선택도 허용한다.

### 규칙 열람 결과

- 만나지 않은 종족·등급의 공개 규정은 `미열람 규칙`으로 표시된다.
- 첫 신청이 도착하면 해당 공개 규정을 읽을 수 있고 등급 규정은 자동 열람된다.
- 손님 카드에는 종족, 등급, 숙박 일수, 공개 개인 선호와 운영 수치만 남긴다.
- 종족×등급 숨은 선호는 결산 뒤 열람되며 모두 양수 점수의 선택 사항이다.
- 빈 이웃 객실 요청은 SR/SSR의 고득점 사생활 선호이며 배정 필수 조건이 아니다.

### 내부 검증

- 데이터 교차참조, 정확한 네 등급, 5개 시나리오, 확률합 100, 단계 잠금, 증축 선행조건을 로딩 때 검증한다.
- 손님과 공사 제안은 직렬화 가능한 시드 상태를 사용하며 동일 입력에서 재현된다.
- 전체 5영업 브라우저 흐름이 최종 결과까지 진행되었다.
- 연박 고정, 객실 마모·정비, 누적 개선, 숨은 선호 열람, SSR 특별 초대가 같은 흐름에서 작동한다.
- 확장 구매는 해법을 넓히지만 진행을 위한 필수 구매로 사용하지 않는다.
- 응대 한도와 실제 사용 가능 객실 수를 분리하고, 두 수치 안에서도 필수 조건 조합을 풀지 못하면 긴급 배정·취소가 발생하는 경로를 유지한다.
- 스키마 4 종료 규칙이 `PREOPENING_COMPLETE`를 판정하고 같은 시드의 중복 완료가 기록을 늘리지 않는지 검증했다.
- 재시작 뒤 실행 기록은 유지되고 런 상태는 다음 시드의 `TITLE`로 초기화된다.
- 1280×720 최종 화면에 종료 기록 카드와 재시작 행동이 스크롤 없이 표시된다.
- 튜토리얼 체크포인트를 저장한 뒤 페이지를 새로 불러오고 같은 시드·단계·손님 명단으로 복구했다.
- 새 런 시작과 엔딩에서는 활성 체크포인트를 제거하며 완료 기록과 진행 세이브가 섞이지 않는다.
- 세이브 스키마 4는 활성 런을 모드별 키에 저장하고, 프로필 스키마 1은 수첩 지식을 별도로 영속화한다. 아침 장부 재열람은 자원·평판·난수·객실·연박을 복원하면서 직접 확인한 숨은 선호만 유지한다.
- 현재 `SHOWCASE` 초청 영업에는 비서 장면과 재검토 행동이 표시되지 않는다. 자동 계약 검증은 시나리오 모드의 장면 진입·간접 대화·아침 복원·외형 선택과 `ENDLESS`의 직접적인 기능 재시도를 각각 검사한다.
- 별도 `?mode=campaign` 경로는 플레이어 성별, 비서 외형, 관계 인물 성별 프리셋·역할별 선택을 런에 고정하며 마녀 역할을 여성으로 검증한다.
- 회색 상자 캠페인은 프롤로그, 2·4일차 챕터 장면, 임시 80G·평판 0 목표와 배드·노말·종족·종족 관계·트루·트루 하렘 엔딩을 실제 브라우저에서 통과한다.
- 종료 기록 스키마 3은 엔딩 계층, 선택된 종족·관계 인물, 실제로 인연을 맺은 손님의 인과적 후일담을 보존한다. 배드 엔딩도 각 인물의 삶 전체를 일괄 붕괴시키지 않는다.
- 스토리 장면 저장 재개, 캠페인·쇼케이스 활성 세이브 격리, 종료 뒤 캠페인 세이브 제거, 프로필 지식 영속화, 스키마 3 쇼케이스 저장 마이그레이션을 자동 검증했다.

### ENDLESS 회색 상자 — GREYBOX · PROVISIONAL · SPINE PASS

- 별도 `?mode=endless` 경로에 시즌 브리핑, 공용 전시품 제안, 5회 영업, 시즌 감사, 다음 시즌과 폐업 기록 상태를 연결했다.
- 개발용 감사 목표는 통과 시즌에 따라 `0 → 2 → 4`로 상승하고 4에서 임시 상한을 둔다.
- 개발용 감사 점수는 시즌 평판 변화 합계에서 마감 긴급 처리 1회당 1점을 차감한다.
- 시즌 통과당 런 명성 +1, `T1`부터 시즌 통과당 위험 단계 +1을 임시 기록한다. 현재 이 값은 손님·시설·아이템·계약 풀을 실제 확장하는 정식 밸런스가 아니다.
- 감사 보고서의 영업별 근거, 목표 대비 차이, 이력, 생존 영업·통과 시즌·런 명성·위험 단계와 최고 기록 저장 계약을 추가했다.
- `tools/test_endless_spine.py`는 시즌 시작 목표 노출, 5회 누적, 통과 후 다음 시즌, 미달 후 폐업, 직접 재시도, 새로고침 복구, 모드 세이브 격리와 1280×720 화면을 실제 Edge에서 검증했다.
- 40시즌·200영업 합성 장기 런에서 최근 영업 결과 20개와 감사 12개만 세이브에 보존하고, 생존 영업·누적 지표·생략 개수는 별도 집계로 유지해 저장 크기가 무한 증가하지 않음을 검증했다. 종료 화면은 최근 감사 5개만 표시한다.
- 이 개발 경로는 `development/campaign-greybox`에만 있으며 `main`과 심사 중인 공개 웹 빌드에는 반영하지 않는다.

## v1 보존 기록 — 최초 2영업 구현 결과

아래 세 시설 경로와 고정 최고점은 v1 자동 검증 증빙이다. v2의 현재 밸런스·콘텐츠 범위·화면 흐름으로 사용하지 않는다.

## 구현된 한 세션

1. 시간 제한 없는 2인 배치 연습 또는 건너뛰기
2. 120초 첫 영업에서 손님 4명 배치
3. 종족·등급 공통 조건과 개인 선호 점수 실시간 확인
4. 첫 영업 수입·평판·평가 정산
5. 방음 객실·라운지·비밀 통로 중 하나 구매
6. 신청 손님 4명을 수용 또는 거절해 정원 5명 구성
7. 120초 두 번째 영업과 시설 효과 배치
8. 최종 수입·평판·평가 확인 및 재시작

모든 화면의 상단에서 운영 수첩을 열 수 있다. 수첩은 호텔 공통 규정, 종족별 숙박 조건, 등급별 응대 규정, 발견·해금 기록을 분리하며 만나지 않은 상위 등급 규정은 첫 신청 등장 전까지 미열람 상태다. 손님 카드에는 종족·등급·개인 선호만 남긴다.

실제 영업은 첫 배치만 무료이고 이미 배정한 손님의 이동·회수·맞바꾸기에 5초를 소비한다. 수첩 열람 중에는 시간이 멈춘다. 마감 시 프런트는 선호를 최적화하지 않고 필수 조건을 만족하는 첫 유효 배치를 적용하며, 불가능할 때는 필요한 손님의 예약을 강제 취소한다.

## 내부 검증 결과

| 경로 | 최고 선호 | 영업 수입 | 평판 변화 | 최종 평가 | 브라우저 |
|---|---:|---:|---:|---:|---|
| 첫 영업 | 19 | 42 | +4 | 35 | PASS |
| 방음 객실 | 26 | 73 | +10 | 60 | PASS |
| 라운지 | 28 | 75 | +10 | 63 | PASS |
| 비밀 통로 | 28 | 74 | +10 | 62 | PASS |

Python 검산기는 모든 유효 배치를 열거하고, Edge 자동 플레이는 각 시설의 대표 최고점 경로를 실제 UI 조작으로 재현한다. 콘솔 오류와 진행 차단은 발견되지 않았다.

별도 시간 제한 회귀 테스트는 연습 완료, 120초 진입, 재배치 5초 차감, 수첩 정지, 긴급 자동 배정을 검증했다. 대표 만료 경로는 최고 19점 대신 11점으로 종료되어 긴급 배정이 점수 최적화를 수행하지 않음도 확인했다. 모든 객실과 충돌하는 합성 예약을 마지막에 추가한 경로에서는 해당 손님만 강제 취소되고 취소 평판 -3이 반영됐다.

배포 ZIP은 별도 임시 폴더에 압축 해제한 뒤 다시 정적 서버로 제공해 비밀 통로 경로 62점까지 통과했다. ZIP 루트에는 `index.html`, `styles.css`, `src/`, `data/`만 포함한다.
