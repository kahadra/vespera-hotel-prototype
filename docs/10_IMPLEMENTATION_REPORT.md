## v2 현재 구현 요약

현재 빌드는 시간 제한 없는 객실 배정 연습과 튜토리얼을 제외한 5회 실제 영업으로 구성된다. 5회 안에 성장 구조를 빠르게 보여 주는 심사용 쇼케이스이며 정식 게임의 해금 속도를 뜻하지 않는다.

### 한 세션에서 작동하는 것

1. `개장 전 초청 영업` 초대장과 진행 표식
2. 2인 객실 배정 연습 또는 건너뛰기
3. 120초 실제 영업 5회와 재배치 5초 비용
4. N/R/SR/SSR 태그와 평판·단계·시드 기반 예약 신청
5. 2회차 R, 3회차 SR 보장과 5회차 쇼케이스 전용 SSR 특별 초대
6. 손님 수용·거절, 필수 숙박 조건, 공개 개인 선호, 현재 만족도 계산
7. 종족×등급 숨은 선호의 결산 열람과 재방문 만족 보너스
8. 연박 손님의 첫 객실 고정과 매일 만족도 재평가
9. 객실 단일 청결도 마모, 낮은 청결도의 만족도·등급별 평판 영향과 영업 사이 유료 청소
10. 연박 객실 선제 청소와 더러운 연박에 한정된 시드 청소 요청
11. 4종족의 인원 시너지와 지정 상극
12. 누적 시설·인테리어와 `F1-D → F2-D → F3-D` 순차 동관 증축
13. 기본 5명에서 증축 객실당 1명씩 증가하는 예약 응대 한도와 별도 물리 객실 한도
14. 예약 단계에서 연박 고정 위치와 사용 불가·미증축 객실을 확인하는 읽기 전용 객실도
15. 손님별 내부 만족도와 `호평 / 무난 / 아쉬움` 정성 후기, 등급별 평판 영향
16. 각 층 엘리베이터와 바로 인접한 A열 소음 객실의 시각적 연결
17. 마지막 결산 뒤 데이터 기반 종료 판정, 엔딩 ID·핵심 지표와 최근 실행 기록 저장
18. 조작·페이지 이탈 체크포인트와 새로고침 뒤 `지난 영업 이어하기`
19. 시나리오 모드 전용 비서 오토마타 아침·마감 장면, 같은 날 아침 복귀와 숨은 선호 기억 상태 계약

영업 사이에는 `영업 준비 / 공사 계약` 한 화면에서 빈 객실과 연박 객실을 선제 청소한다. 청결도가 내려간 연박이 남아 있으면 같은 시드에서 재현되는 35% 요청을 막간 최대 1건·동일 체류 최대 1회 검사한다. 수락은 8G·청결도 100·평판 +1, 거절은 평판 -1·상태 유지·같은 막간 재청소 차단이며 모두 `PROVISIONAL` 값이다. 공사 제안은 `동관 증축`과 `시설·인테리어`로 나누며 각 분류에서 최대 1건을 계약한 뒤 다음 영업으로 간다. 아무 계약도 하지 않는 선택도 허용한다.

### 규칙 열람 결과

- 만나지 않은 종족·등급의 공개 규정은 `미열람 규칙`으로 표시된다.
- 첫 신청이 도착하면 해당 공개 규정을 읽을 수 있고 등급 규정은 자동 열람된다.
- 손님 카드에는 종족, 등급, 숙박 일수, 공개 개인 선호와 운영 수치만 남긴다.
- 종족×등급 숨은 선호는 결산 뒤 열람되며 모두 양수 점수의 선택 사항이다.
- 빈 이웃 객실 요청은 SR/SSR의 고득점 사생활 선호이며 배정 필수 조건이 아니다.
- 성기사 종족 공통 하드 제약에는 소음 금지가 없다. Rowan의 엘리베이터 옆 선호는 유효하며, 소음 금지는 SR·SSR 등급 하드 제약에서만 합성된다. 규칙 UI는 `종족 공통 / 등급 / 개인` 출처를 구분한다.
- SSR 등급 공통 불호의 햇빛 조건은 성기사 공통 햇빛 선호와 직접 충돌하므로 `NEAR_FACILITY LOUNGE`로 교체했다. 데이터 검증기는 종족·등급·종족×등급 공통층에서 동일 조건이 선호와 불호에 중복되면 거부하고, 의도적인 손님 개인 예외만 허용한다.

- 전체 5영업 브라우저 흐름이 최종 결과까지 진행되었다.

### 런타임 재정 시뮬레이터 정합성 — PASS · PROVISIONAL

- 기능 커밋 `564c204`에서 실제 JavaScript 재정 커널의 독립 Python 미러를 추가하고 기존 경제 프런티어 분석기가 이를 사용하도록 바꿨다. 이제 분석기는 이미 해결된 수입·유지비·재가동·객실 정비와 선지급 준비비를 런타임 순서로 반영하고, 상환은 항상 명시적인 `manualRepayment` 선택으로 제출한다.
- JavaScript 오라클은 복제된 기대 출력을 읽지 않고 실제 `src/campaign-finance.js`를 import한다. 정확한 7필드 결과 확정과 `{ manualRepayment }` 정산을 공통 fixture 18경로에서 Python과 비교해 12개 수락·6개 거부, 원장 278행·추적 851건이 일치했다. 엄격 로더 2건, Python 상태 검증기 5건, 공개 API 형상 4건도 PASS했다.
- 기존 실제 Edge 재정 계약의 거부 사례 92건, 형식 캠페인 56/70일 통합과 진행 회귀도 PASS했다. 다만 새 정합성 게이트 자체의 범위는 `RESOLVED_DAILY_FINANCE_TRANSITIONS` 재정 커널이며 손님 생성·배치·점수·공사 및 객실 자격·전체 `GameController` 롤백을 입증하지 않는다.
- fixture와 정책은 `PROVISIONAL`, 밸런스 판정은 `NOT_EVALUATED`다. 이 결과는 구현 정합성 증거이지 시작 운전자금·부채·허들·유지비·재가동비의 난도나 재미가 적절하다는 판정이 아니다.
- 잠정 경계 생성기는 5일 수입 참고치 두 개와 기계적 중간값을 각각 5개 phase로 회전한 15개 trace, 상환 곡선 3개, 재가동비 배분 2개, 수치 축 5개를 사용해 90개 구조·450개 조건부 경계를 기록했다. 중심값은 10/15 trace가 day 56 부채 0에 도달했고, 64개 셀은 다른 중심값을 고정한 상태에서 축의 0값으로도 다섯 phase 공통 경계를 만들지 못했다.
- 이 결과는 확률분포·완주율·난도·밸런스 판정이 아니며 서로 다른 단일 축 최대값을 합친 공동 실행 가능 번들도 아니다. 생성기가 보고한 고유 시뮬레이션 3,642회는 cache miss telemetry이고 독립 실행 횟수 증명이 아니다.

### ENDLESS 회색 상자 — GREYBOX · PROVISIONAL · SPINE PASS

- 별도 `?mode=endless` 경로에 시즌 브리핑, 공용 전시품 제안, 5회 영업, 시즌 감사, 다음 시즌과 폐업 기록 상태를 연결했다.
- 개발용 감사 목표는 통과 시즌에 따라 `0 → 2 → 4`로 상승하고 4에서 임시 상한을 둔다.
- 개발용 감사 점수는 시즌 평판 변화 합계에서 마감 긴급 처리 1회당 1점을 차감한다.
- 시즌 통과당 런 명성 +1, `T1`부터 시즌 통과당 위험 단계 +1을 임시 기록한다. 현재 이 값은 손님·시설·아이템·계약 풀을 실제 확장하는 정식 밸런스가 아니다.
- 감사 보고서의 영업별 근거, 목표 대비 차이, 이력, 생존 영업·통과 시즌·런 명성·위험 단계와 최고 기록 저장 계약을 추가했다.
- `tools/test_endless_spine.py`는 시즌 시작 목표 노출, 5회 누적, 통과 후 다음 시즌, 미달 후 폐업, 직접 재시도, 새로고침 복구, 모드 세이브 격리와 1280×720 화면을 실제 Edge에서 검증했다.

- 이 개발 경로는 `development/campaign-greybox`에만 있다. 심사는 종료됐으며 기존 `main`, 공개 URL과 ZIP은 새 정식판 산출물이 아니라 과거 쇼케이스 증빙으로 별도 변경 지시 전까지 보존한다.

### Electron 데스크톱 스파이크 — FUNCTIONAL PASS · NATIVE INCIDENT OPEN · NOT RELEASE READY

- Electron 44.0.0과 제한된 preload를 기존 웹 코어에 부착했다. `vespera://app/`은 허용된 게임 자산만 제공하며 renderer는 sandbox·context isolation·web security를 유지하고 Node 전역·임의 IPC·외부 내비게이션에 접근하지 못한다.
- 쿼리 없는 Electron 기동은 캠페인·무한 영업·초청 영업을 선택하는 모드 허브를 표시한다. 쿼리 없는 브라우저는 이전처럼 `SHOWCASE`를 시작하므로 웹 회귀 계약은 바꾸지 않았다. 실제 외곽 창 960×600의 콘텐츠 영역 944×561에서 overflow 없이 세 모드를 노출했고 CDP Tab→Space 진입을 통과했다. 네트워크 오프라인 상태에서도 DOM 클릭 위임으로 허브와 `SHOWCASE` 데이터를 로드했다.
- Electron에서는 같은 Storage 키와 게임 payload를 OS `userData/save-data/v1/profiles/local` 아래 프로필·실행 기록·모드별 활성 런 파일로 분리한다. 웹 개발 경로의 `localStorage` fallback은 보존한다.
- `CAMPAIGN`, `ENDLESS`, `SHOWCASE` 파일은 함께 존재하고 재시작 뒤 선택한 모드의 단계·시드·영업일을 정확히 재개한다. 캠페인 `completeRun()`의 `CAMPAIGN_INTERRUPTED` 종결과 무한 영업 5-operation 감사 실패 종결은 대상 모드에만 tombstone을 남겼고, 비대상 primary·backup 원문 바이트와 재개 결과는 변하지 않았다.
- 파일 envelope 스키마 1은 게임 세이브 스키마 7과 별개이며 checksum·revision·임시 기록·동기화·원자 교체·backup·손상 격리·삭제 tombstone·용량 상한을 제공한다.
- 종료 기록은 저장 raw readback에 성공한 뒤에만 활성 런을 지운다. 예외 또는 silent no-op을 주입한 회귀에서 정확한 STORY 체크포인트와 미확정 실행 기록이 보존되고 새 컨트롤러가 같은 단계·시드로 재개했다.
- 파일 저장 단위 테스트 `9/9`, 모드 허브 단위 테스트 `10/10`(통합 `19/19`), 개발 Electron과 폴더 패키지 `VesperaHotel.exe`가 모두 PASS했다. 첫 프로필에서 허브와 세 모드 저장을 공존시키는 동안 측정한 17회 FileStorage mutation의 동기 쓰기는 개발 p95 14.264ms, 최종 패키지 p95 11.206ms였다. 양방향 종단 격리는 별도 프로필·프로세스에서 PASS했으며 두 증거 모두 장기 성능 판정으로 확대하지 않는다.
- 제한된 Codex 관리 실행의 Windows Mojo IPC 오류 `0x5` 뒤 일반 사용자 권한 재실행은 별도 시스템 설치나 `--no-sandbox` 없이 Electron sandbox를 유지한 채 개발·패키지 기능 회귀를 통과했다. 그러나 이후 모드 허브 본창과 함께 `0x80000003` 예외 창이 다시 관측돼 환경 한정 사건 종료 판단을 철회했다. 정확한 자식 프로세스 역할과 dump를 확보하기 전까지 기능 PASS를 네이티브 안정성 PASS로 확대하지 않는다.
- 현재 산출물은 installer·서명·Steam 계정·Cloud·웹 저장 이전·클린 PC 설치·정식 56/70일 캠페인 파일 완주와 장기 무한 영업이 없는 스파이크다. 상세 증거와 한계는 `30_DESKTOP_RUNTIME_SPIKE.md`를 따른다.

## v1 보존 기록 — 최초 2영업 구현 결과

아래 세 시설 경로와 고정 최고점은 v1 자동 검증 증빙이다. v2의 현재 밸런스·콘텐츠 범위·화면 흐름으로 사용하지 않는다.

## 구현된 한 세션

1. 시간 제한 없는 2인 배치 연습 또는 건너뛰기
2. 120초 첫 영업에서 손님 4명 배치
3. 종족·등급 공통 조건과 개인 선호 점수 실시간 확인
4. 첫 영업 수입·평판·평가 정산
5. 방음 객실·라운지·비밀 통로 중 하나 구매
6. 신청 손님 4명을 수용 또는 거절해 정원 5명 구성
7. 120초 두 번째 영업과 시설 효과 배치
8. 최종 수입·평판·평가 확인 및 재시작

모든 화면의 상단에서 운영 수첩을 열 수 있다. 수첩은 호텔 공통 규정, 종족별 숙박 조건, 등급별 응대 규정, 발견·해금 기록을 분리하며 만나지 않은 상위 등급 규정은 첫 신청 등장 전까지 미열람 상태다. 손님 카드에는 종족·등급·개인 선호만 남긴다.

실제 영업은 첫 배치만 무료이고 이미 배정한 손님의 이동·회수·맞바꾸기에 5초를 소비한다. 수첩 열람 중에는 시간이 멈춘다. 마감 시 프런트는 선호를 최적화하지 않고 필수 조건을 만족하는 첫 유효 배치를 적용하며, 불가능할 때는 필요한 손님의 예약을 강제 취소한다.

Python 검산기는 모든 유효 배치를 열거하고, Edge 자동 플레이는 각 시설의 대표 최고점 경로를 실제 UI 조작으로 재현한다. 콘솔 오류와 진행 차단은 발견되지 않았다.

별도 시간 제한 회귀 테스트는 연습 완료, 120초 진입, 재배치 5초 차감, 수첩 정지, 긴급 자동 배정을 검증했다. 대표 만료 경로는 최고 19점 대신 11점으로 종료되어 긴급 배정이 점수 최적화를 수행하지 않음도 확인했다. 모든 객실과 충돌하는 합성 예약을 마지막에 추가한 경로에서는 해당 손님만 강제 취소되고 취소 평판 -3이 반영됐다.

배포 ZIP은 별도 임시 폴더에 압축 해제한 뒤 다시 정적 서버로 제공해 비밀 통로 경로 62점까지 통과했다. ZIP 루트에는 `index.html`, `styles.css`, `src/`, `data/`만 포함한다.
