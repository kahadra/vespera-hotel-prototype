# 기능적 뼈대, 세이브와 실행 기록

- 상태: `ACTIVE · SPINE FIRST`
- 현재 구현: v2 쇼케이스 보존, 회색 상자 캠페인·무한 영업 종단 검증, Electron 파일 저장·재실행 스파이크 PASS
- 목적: 설정과 콘텐츠를 늘리기 전에 새 게임부터 엔딩·기록까지 끊기지 않는 공통 실행 계약을 고정한다.

## 1. 완성의 정의

게임의 뼈대는 다음 연결이 실제 상태 전환과 저장 데이터로 한 번 이상 끝까지 통과할 때 완성으로 판정한다.

```text
새 게임
→ 런 초기화
→ 영업 준비
→ 예약
→ 배치
→ 정산
→ 진행 판정
→ 다음 영업 또는 종료 판정
→ 엔딩
→ 실행 기록
→ 재시작·불러오기
```

기본 주소의 v2 `SHOWCASE`는 기존 5회 초청 영업을 그대로 통과한다. 별도 `?mode=campaign` 회색 상자 경로는 `새 게임 설정 → 프롤로그 → DAY_OPENING → 영업 → RESULT_REVIEW → 챕터 장면 → 여섯 단계 엔딩 판정 → 관계 인물 후일담 → 실행 기록`을 실제로 통과하며, 스토리 장면에서 페이지를 다시 불러와도 이어진다. `?mode=endless`도 `시즌 브리핑 → 전시품 제안 → 5회 영업 → 시즌 감사 → 다음 시즌 또는 폐업 기록`을 실제로 통과하고 감사 화면에서 새로고침해도 같은 보고서를 복구한다. 두 경로의 회색 상자 수치와 콘텐츠는 정식 규칙이 아니다.

## 2. 코어와 외부 부착 콘텐츠의 경계

| 기능적 뼈대 · 코드 변경이 필요한 영역 | 외부 부착 콘텐츠 · 데이터와 자산으로 늘리는 영역 |
| --- | --- |
| 허용된 상태 전환과 진행 판정 | 챕터·영업·사건 장면 목록 |
| 시드와 런 초기화 | 손님·종족·직업·시설·아이템 |
| 스테이지·달력 진행과 하루 일정 합성 | 계절 구간, 7일 주기, 공휴일·행사일과 수요 변형 데이터 |
| 예약·배치·규칙 평가·정산 | 개별 조건표와 밸런스 수치 |
| 경제·평판·목표의 공통 지표 | 목표 금액·기한·감사 기준 |
| 세이브 버전·검증·마이그레이션 | 대사·사건 선택지·초상·도트·오디오 |
| 데이터 기반 종료 조건 평가기 | 기본·종족·관계·실패 엔딩 정의 |
| 중복 없는 실행 기록과 기록실 조회 | 엔딩 제목·설명·연출 |
| 콘텐츠 ID·참조·도달 가능성 검증 | 추가 콘텐츠 팩과 변형 규칙 |
| 시드 고정형 전시품 제안·선택·패시브 평가 | 공용·종족·관계 인물별 전시품 이름·유래·효과 |

새 종족이나 설정은 기존 뼈대를 바꾸지 않고 등록할 수 있을 때만 제작한다. 콘텐츠 하나를 붙이기 위해 상태 머신, 저장 형식 또는 결과 계산을 매번 고쳐야 한다면 뼈대가 아직 끝난 것이 아니다.

## 2.5. INTERNAL SPOILER · 세계관과 세이브 경험의 계약

- 플레이어 캐릭터는 인간 지배인이며, 예지안은 지배인의 의지와 무관하게 작용한다. 오토마타는 플레이어 캐릭터가 아니라 지배인의 지시 아래 접객·시설·기록 실무를 맡는다.
- 시드는 오토마타가 만든 모의 환경이 아니라 서로 갈라질 수 있는 가능 세계다.
- 정산 결과는 플레이어가 선택하기 전까지 현실과 예지 어느 쪽으로도 확정되지 않은 상태다.
- `계속 진행`을 선택하면 해당 경로 전체를 현실로 관측·확정한다. 이때 지나온 영업은 예지나 시뮬레이션이 아니다.
- `이번 영업 다시`를 선택한 경우에만 방금 경로가 예지 시뮬레이션으로 귀속되고, 직전 영업 시작점의 다른 가능성을 선택한다.
- 이 구조는 양자역학의 미관측 상태와 관측에 따른 확정을 세계관적으로 차용한 것이며 시간 역행이나 오토마타 계산이 아니다.
- 한 번에 여러 영업을 되돌리는 목록은 제공하지 않는다. 정산을 받아들이면 해당 영업의 즉시 재시도 권한은 닫힌다.
- 정식 캠페인의 장기 복귀점은 챕터 시작 체크포인트다. 챕터 내부에서는 직전 영업 정산만 다시 할 수 있다.
- 예지로 귀속한 가능성의 자원, 시설, 객실 상태, 사건·관계 수치는 모두 복원한다. 지배인이 직접 확인한 기계적 숨은 선호만 예지 기억으로 유지한다.
- 다른 인물은 폐기한 가능성을 겪지 않았으므로 그 안의 대화, 관계 상승, 증거 확보와 엔딩 플래그는 유지하지 않는다.
- 오토마타는 중립 접객과 일반 기록 보관만 담당하며 예지안의 원인이나 미래 계산에 관여하지 않는다.
- 플레이어 UI에는 위 원리를 명명하지 않는다. 정산에는 평범한 `비서에게 마감 장부를 건넨다` 행동만 두고, 마감 대화에서 `아침 장부부터 다시 읽어 달라`는 업무상 표현으로 재검토를 선택한다.
- 재검토 뒤 아침 장면의 기시감 대사와 이미 알고 있는 숨은 선호가 단서가 된다. 비서는 해설자가 아니라 이상 징후를 함께 겪는 관찰자다.
- 비서 오토마타 외형은 캠페인 새 게임에서 `MALE` 또는 `FEMALE`을 고른다. 이 값은 초상·음성·호칭 표현만 바꾸고 상태 전환과 장면 역할을 바꾸지 않는다.
- `DAY_OPENING`과 `RESULT_REVIEW`, 비서를 통한 간접 재검토는 시나리오 캠페인 전용이다. 무한 영업은 같은 복원 엔진을 `이번 영업 다시` 버튼으로 직접 호출하며 세계관 설명이나 비서 장면을 붙이지 않는다. `SHOWCASE`는 재시도를 렌더링하지 않는다.

## 3. 상태와 저장 영역

| 영역 | 수명 | 포함 | 금지 |
| --- | --- | --- | --- |
| 프로필 | 여러 런 | 수첩 발견, 업적, 해금 콘텐츠 ID, 전시품 제안·획득·발동 도감과 무한 영업 후보군 자격, 최고 기록 | 현재 골드·시설·관계 수치, 현재 보유 전시품 |
| 모드 런 | 새 게임부터 엔딩까지 | 시드, 진행 위치, 스테이지·하루 인덱스, 압축 계절·주차·요일, 자원·상속 부채·누적 상환액·다음 챕터 최소액·본편 종단 부채 해결 플래그·시작 운전자금, 시설, 평판, 사건·관계 플래그, 현재 열린 후보군과 보유·대기 중 전시품 | 다른 모드의 진행 상태 |
| 체크포인트 | 런 진행 중 | 챕터 시작 상태, 직전 영업 시작 상태, 해당 하루 일정 설명자와 적용 수요 변형, 부채 잔액·누적 상환 이력, 콘텐츠·세이브 버전 | 렌더링 전용 DOM 상태 |
| 실행 기록 | 런 종료 뒤 | 모드, 시드, 엔딩 ID·계층, 종족·관계 인물 선택, 인과적으로 연결된 후일담, 핵심 지표 | 전체 런 상태 복제, 숨은 미발견 정보 |

실행 기록은 세이브가 아니다. 종료한 런을 다시 진행시키지 않고 결과와 재현 키만 보존한다. 웹 개발 경로는 브라우저 `localStorage`에 최근 20개를 저장하고, Electron 스파이크는 같은 키·payload를 프로필·실행 기록·모드별 활성 런 파일로 분리한다. 같은 네임스페이스와 시드의 기록은 하나만 유지한다.

Electron의 저장 루트는 OS별 `userData/save-data/v1/profiles/local`이다. 파일 envelope 스키마 1은 게임의 세이브 스키마 6·프로필 스키마 1을 감싸며 checksum·revision·파일별 원자 교체·직전 정상 backup·손상 격리·삭제 tombstone을 제공한다. 여러 파일 전체를 하나의 transaction으로 묶지는 않는다. 대신 실행 기록 raw readback이 성공한 뒤 활성 런을 tombstone으로 제거하는 순서를 지켜, 실패 시 완료 기록과 재개 가능한 체크포인트 중 최소한 체크포인트를 잃지 않는다.

정식 캠페인에서는 `스테이지 1개 = 달력 하루 1일 = 영업 1회`를 저장 계약으로 사용한다. `PROVISIONAL` 제작 기준으로 본편은 14일짜리 4계절의 56일이며, 트루 분기는 56일 경계를 유지한 채 추가 계절 14일을 이어 총 70일이 된다. 계절 하나는 2주, `평일 10일·주말 4일`이고 7스테이지를 1주로 보아 6·7일차를 주말로 둔다. 날짜는 고정 시나리오 배열의 인덱스가 아니며, 계절 구간, 주차·요일, 특정 스테이지 또는 계절 내 위치의 공휴일·행사일, 시나리오·수요 변형 참조를 합친 하루 일정 설명자다. 직전 영업을 다시 할 때는 같은 날짜와 설명자를 복원하며 손님 수·등급·종족 풀 변형을 다시 추첨하지 않는다.

`src/campaign-progress.js`는 실제 완료 스테이지 수와 현재 정상 영업, 56일 본편 종단, 명시적 gate 통과 뒤의 57~70일 전환을 순수 전이 계약으로 구현한다. 모든 스테이지가 달력의 정상 영업일 하나를 소비하며 별도 회복 종류는 없다. 결과 식별자는 `stageNumber + operationKind + templateIndex`를 사용하되 `operationKind`는 `NORMAL`만 허용한다. 상태·저장·실행 기록 모듈은 합성 `FORMAL_CAMPAIGN` 데이터를 주입했을 때 이 권위로 56/70일을 완주한다. 다만 현재 5개 시나리오의 나머지 연산 순환은 진행·저장 연결을 검증하기 위한 `GREYBOX_ONLY_STAGE_MODULO`이고 `productionReady: false`다. `loadGameData`와 URL에는 이 모드를 등록하지 않았으며, 생성기 또는 검증된 명시 계획이 생기기 전까지 플레이 가능한 정식 캠페인으로 활성화하지 않는다.

챕터 경계는 `CH1 day 1~7 봄 전반 → CH2 day 8~14 봄 후반 → CH3 day 15~28 여름 → CH4 day 29~42 가을 → CH5 day 43~56 겨울`이다. day 56에 부채를 전액 상환하고 트루 조건을 만족한 런만 `day 57~70 추가 계절`의 숨은 CH6 상태로 전환한다. 이때 저장된 부채 해결 플래그를 검사하며 추가 14일을 상환 유예로 사용하지 않는다.

추가 상환은 해당 영업 결과를 확정한 뒤 정산 흐름에서 커밋한다. 직전 영업 재검토로 영업 시작 체크포인트를 복원하면 아직 확정하지 않은 상환 선택과 상환 이력도 함께 롤백해 골드 차감이나 원금 감소가 중복되지 않게 한다. 챕터 마지막 날에는 당일 수입·유지비와 선택적 추가 상환을 확정한 다음 누적 최소액을 검사한다.

## 4. 데이터 기반 종료 계약

`data.run_completion`은 우선순위가 있는 종료 규칙과 반드시 존재하는 대체 결말을 가진다. 코드는 엔딩 ID나 문구를 하드코딩하지 않는다.

```json
{
  "record_namespace": "vespera.preopening.v2",
  "ending_rules": [
    {
      "id": "PREOPENING_COMPLETE",
      "priority": 100,
      "outcome": "COMPLETE",
      "conditions": [
        {"metric": "completed_nights", "operator": "GTE", "value": 5}
      ]
    }
  ],
  "fallback_ending": {"id": "PREOPENING_INCOMPLETE", "outcome": "INCOMPLETE"}
}
```

공통 평가기가 제공하는 지표는 완료 영업 수, 누적 수입·평판, 최종 골드·평판, 수용·거절·취소 손님 수, 보유 개선 수, 긴급 배정 영업 수와 흘려보낸 가능성 수다. 회색 상자 캠페인은 여기에 챕터 허들 실패, 종족 우호도·협약·최고 우호 종족, 몽마 엔딩용 타종족 우호 교류망, 관계 인물 필수 사건 완료 수, 진상 증거와 평화 협약 지표를 추가한다. 무한 영업 기록은 폐업 여부, 생존 영업 수, 통과 시즌 수, 마지막·최고 감사 점수, 목표와 차이, 런 명성, 위험 단계를 별도로 보존한다. 존재하지 않는 지표나 지원하지 않는 비교 연산자는 데이터 검증에서 거부한다.

우선순위가 높은 규칙부터 평가하며 첫 일치만 채택한다. 어떤 규칙도 맞지 않으면 대체 결말을 사용하므로 엔딩 화면 없이 런이 끝나는 상태를 허용하지 않는다.

## 5. 현재 구현된 회색 상자 연결

- `src/run.js`: 런 요약, 우선순위형 다단계 종료 규칙 평가, 버전 6 실행 기록, 형식 캠페인의 실제 완료 스테이지·진행 권위·수입·유지비·재가동·정비·상환·잔여 부채, 실패 전 지급한 준비비를 포함한 총지출과 day 56 해결 증거·운영자금 부족 실패 증거, 종족 엔딩의 지배인 선택지, 관계 인물 후일담과 캐릭터 표현 설정 기록. 기록 쓰기와 raw readback 실패는 `RUN_RECORD_WRITE_FAILED`로 종료 확정을 중단한다.

## 7. 확정된 경제 계약과 남은 사용자 결정 게이트

### 확정된 P0 방향

- 플레이어에게 보이는 캠페인 목표는 기한 안에 상속 부채를 상환해 호텔을 지키는 것이다.
- 정식 캠페인은 5일 고정이 아니며 `스테이지 1개 = 하루 1일 = 영업 1회`로 진행한다. `PROVISIONAL` 기준 본편은 `4계절 × 14일 = 56일`, 트루 분기는 56일 뒤 추가 계절 14일을 이어 총 70일이다. 계절당 2주를 `평일 10일·주말 4일`로 구성하고, 공휴일·특별 행사일이 손님 수·등급·종족 풀을 데이터로 바꾼다.
- 본편 챕터는 `CH1 1~7 봄 전반`, `CH2 8~14 봄 후반`, `CH3 15~28 여름`, `CH4 29~42 가을`, `CH5 43~56 겨울`로 나눈다. 숨은 CH6은 day 57~70의 추가 계절이다.
- 첫 영업과 최소 재가동을 위한 일부 시작 운전자금을 지급하되 정확한 금액은 경제 시뮬레이션 뒤 확정한다.
- 기존 객실·시설은 새로 짓는 것이 아니라 비활성 구역을 재가동하며, 선택한 다음 날부터 사용할 수 있다.
- 활성 객실·시설 규모에 따른 오토마타 유지비를 매일 자동 차감한다. 활성 규모, 상환 잔액, 다음 차감액은 모드 런 상태와 체크포인트에 포함한다.
- 각 챕터 결산에서 누적 최소 의무 상환액을 검사하고, 매 영업 정산에서는 플레이어가 추가 상환을 선택할 수 있다. 챕터 1은 첫 소액 상환, 챕터 5는 day 56 전액 상환을 요구한다.
- CH1~4의 누적 의무 상환 미달은 해당 챕터의 운영 실패로 즉시 배드 엔딩이며, day 56 부채 미상환도 같은 실패 계층으로 닫는다. 별도 회복 영업은 두지 않고 목표·부족액·남은 영업일·일평균 필요 상환액을 사전에 표시한다.
- 당일 수입과 보유금으로 오토마타 유지비를 감당하지 못하면 별도 미납 채무나 음수 현금을 만들지 않고 즉시 운영 실패한다. 영업 전에 이미 지불한 재가동·객실 정비와 그 결과는 보존하고, 실패 영업의 수입·평판·손님·객실 마모·유지비는 적용하지 않되 시도한 수입·확정 준비 비용·부족액은 실행 기록에 남긴다.
- day 56에 부채를 해결한 런만 트루 조건을 검사해 숨은 CH6으로 진행한다. 추가 14일은 부채 상환 유예가 아니다.
- 현재 5영업 결과는 하루 수입 규모 참고치로만 사용한다. `56/70일`과 계절당 14일은 콘텐츠 밀도 검증 뒤 조정할 수 있으며, 공휴일·행사일 명칭과 효과, 시작 운전자금, 원금·챕터별 누적 최소액·비율, 재가동 비용과 유지비 표는 데이터 기반 시뮬레이션으로 정한다.

### 남은 사용자 결정

1. **P1 · 캠페인 슬롯 수:** 가능 세계를 몇 개의 독립 캠페인 슬롯으로 보존할지
2. **P1 · 완전 초기화 범위:** 실행 기록과 운영 수첩까지 지우는 별도 프로필 초기화를 제공할지
3. **P1 · 압축 달력 상세:** 공휴일·특별 행사일의 명칭·배치·수요 변형 수치
4. **P1 · 상환 데이터:** 시작 운전자금과 부채 원금, 챕터별 누적 최소 상환액·비율의 정확한 수치

수치·이름·대사는 위 결정 뒤에도 데이터로 교체할 수 있다. 확정 전에는 가칭과 명시적인 임시값을 사용하되 콘텐츠 양을 늘리지 않는다.

## 8. 뼈대 완료 게이트

- 새 게임에서 배드·노말·종족·종족 관계·트루·트루 하렘의 여섯 엔딩 계층에 각각 한 번 실제 도달 가능
- 종료 규칙이 없거나 잘못된 콘텐츠는 시작 전에 검증 실패
- 웹 세이브 뒤 새로고침하고 Electron 파일 세이브 뒤 프로세스를 재실행해 같은 시드와 진행 위치 복구
- 종료 기록 쓰기·readback이 실패하면 실행 기록을 확정하거나 활성 체크포인트를 지우지 않고 재개 가능
- 엔딩 기록을 두 번 호출해도 중복 생성되지 않음
- 프로필, 캠페인 런, 무한 영업 런의 자원과 관계 상태가 섞이지 않음
- 전시품 도감은 프로필에 남고 보유 패시브는 각 런에만 저장되며, 체크포인트 복원과 새로고침으로 후보를 재추첨하거나 중복 획득할 수 없음
- 임시 종족·인물·장면 묶음을 교체해도 상태 머신과 저장 코드 변경 없음
- 자동 회귀가 새 게임, 저장·불러오기, 여섯 엔딩 계층과 우선순위, 관계 인물 후일담, 기록, 재시작을 모두 통과

이 게이트 전에는 대량 손님·종족·시설·관계 장면과 최종 아트 제작을 우선 작업으로 올리지 않는다.
