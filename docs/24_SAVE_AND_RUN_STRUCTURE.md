# 기능적 뼈대, 세이브와 실행 기록

- 상태: `ACTIVE · SPINE FIRST`
- 현재 구현: v2 쇼케이스 보존과 회색 상자 캠페인의 종단 연결
- 목적: 설정과 콘텐츠를 늘리기 전에 새 게임부터 엔딩·기록까지 끊기지 않는 공통 실행 계약을 고정한다.

## 1. 완성의 정의

게임의 뼈대는 다음 연결이 실제 상태 전환과 저장 데이터로 한 번 이상 끝까지 통과할 때 완성으로 판정한다.

```text
새 게임
→ 런 초기화
→ 영업 준비
→ 예약
→ 배치
→ 정산
→ 진행 판정
→ 다음 영업 또는 종료 판정
→ 엔딩
→ 실행 기록
→ 재시작·불러오기
```

기본 주소의 v2 `SHOWCASE`는 기존 5회 초청 영업을 그대로 통과한다. 별도 `?mode=campaign` 회색 상자 경로는 `새 게임 설정 → 프롤로그 → DAY_OPENING → 영업 → RESULT_REVIEW → 챕터 장면 → 여섯 단계 엔딩 판정 → 관계 인물 후일담 → 실행 기록`을 실제로 통과하며, 스토리 장면에서 페이지를 다시 불러와도 이어진다. 현재 연결은 정식 콘텐츠가 아니라 상태·세이브·종료 계약을 검증하는 임시 5영업 경로다.

## 2. 코어와 외부 부착 콘텐츠의 경계

| 기능적 뼈대 · 코드 변경이 필요한 영역 | 외부 부착 콘텐츠 · 데이터와 자산으로 늘리는 영역 |
| --- | --- |
| 허용된 상태 전환과 진행 판정 | 챕터·영업·사건 장면 목록 |
| 시드와 런 초기화 | 손님·종족·직업·시설·아이템 |
| 예약·배치·규칙 평가·정산 | 개별 조건표와 밸런스 수치 |
| 경제·평판·목표의 공통 지표 | 목표 금액·기한·감사 기준 |
| 세이브 버전·검증·마이그레이션 | 대사·사건 선택지·초상·도트·오디오 |
| 데이터 기반 종료 조건 평가기 | 기본·종족·관계·실패 엔딩 정의 |
| 중복 없는 실행 기록과 기록실 조회 | 엔딩 제목·설명·연출 |
| 콘텐츠 ID·참조·도달 가능성 검증 | 추가 콘텐츠 팩과 변형 규칙 |
| 시드 고정형 전시품 제안·선택·패시브 평가 | 공용·종족·관계 인물별 전시품 이름·유래·효과 |

새 종족이나 설정은 기존 뼈대를 바꾸지 않고 등록할 수 있을 때만 제작한다. 콘텐츠 하나를 붙이기 위해 상태 머신, 저장 형식 또는 결과 계산을 매번 고쳐야 한다면 뼈대가 아직 끝난 것이 아니다.

## 2.5. INTERNAL SPOILER · 세계관과 세이브 경험의 계약

- 플레이어 캐릭터는 인간 지배인이며, 예지안은 지배인의 의지와 무관하게 작용한다. 오토마타는 플레이어 캐릭터가 아니라 지배인의 지시 아래 접객·시설·기록 실무를 맡는다.
- 시드는 오토마타가 만든 모의 환경이 아니라 서로 갈라질 수 있는 가능 세계다.
- 정산 결과는 플레이어가 선택하기 전까지 현실과 예지 어느 쪽으로도 확정되지 않은 상태다.
- `계속 진행`을 선택하면 해당 경로 전체를 현실로 관측·확정한다. 이때 지나온 영업은 예지나 시뮬레이션이 아니다.
- `이번 영업 다시`를 선택한 경우에만 방금 경로가 예지 시뮬레이션으로 귀속되고, 직전 영업 시작점의 다른 가능성을 선택한다.
- 이 구조는 양자역학의 미관측 상태와 관측에 따른 확정을 세계관적으로 차용한 것이며 시간 역행이나 오토마타 계산이 아니다.
- 한 번에 여러 영업을 되돌리는 목록은 제공하지 않는다. 정산을 받아들이면 해당 영업의 즉시 재시도 권한은 닫힌다.
- 정식 캠페인의 장기 복귀점은 챕터 시작 체크포인트다. 챕터 내부에서는 직전 영업 정산만 다시 할 수 있다.
- 예지로 귀속한 가능성의 자원, 시설, 객실 상태, 사건·관계 수치는 모두 복원한다. 지배인이 직접 확인한 기계적 숨은 선호만 예지 기억으로 유지한다.
- 다른 인물은 폐기한 가능성을 겪지 않았으므로 그 안의 대화, 관계 상승, 증거 확보와 엔딩 플래그는 유지하지 않는다.
- 오토마타는 중립 접객과 일반 기록 보관만 담당하며 예지안의 원인이나 미래 계산에 관여하지 않는다.
- 플레이어 UI에는 위 원리를 명명하지 않는다. 정산에는 평범한 `비서에게 마감 장부를 건넨다` 행동만 두고, 마감 대화에서 `아침 장부부터 다시 읽어 달라`는 업무상 표현으로 재검토를 선택한다.
- 재검토 뒤 아침 장면의 기시감 대사와 이미 알고 있는 숨은 선호가 단서가 된다. 비서는 해설자가 아니라 이상 징후를 함께 겪는 관찰자다.
- 비서 오토마타 외형은 캠페인 새 게임에서 `MALE` 또는 `FEMALE`을 고른다. 이 값은 초상·음성·호칭 표현만 바꾸고 상태 전환과 장면 역할을 바꾸지 않는다.
- `DAY_OPENING`과 `RESULT_REVIEW`, 비서를 통한 간접 재검토는 시나리오 캠페인 전용이다. 무한 영업은 같은 복원 엔진을 `이번 영업 다시` 버튼으로 직접 호출하며 세계관 설명이나 비서 장면을 붙이지 않는다. `SHOWCASE`는 재시도를 렌더링하지 않는다.

## 3. 상태와 저장 영역

| 영역 | 수명 | 포함 | 금지 |
| --- | --- | --- | --- |
| 프로필 | 여러 런 | 수첩 발견, 업적, 해금 콘텐츠 ID, 전시품 제안·획득·발동 도감과 무한 영업 후보군 자격, 최고 기록 | 현재 골드·시설·관계 수치, 현재 보유 전시품 |
| 모드 런 | 새 게임부터 엔딩까지 | 시드, 진행 위치, 자원, 시설, 평판, 사건·관계 플래그, 현재 열린 후보군과 보유·대기 중 전시품 | 다른 모드의 진행 상태 |
| 체크포인트 | 런 진행 중 | 챕터 시작 상태, 직전 영업 시작 상태, 콘텐츠·세이브 버전 | 렌더링 전용 DOM 상태 |
| 실행 기록 | 런 종료 뒤 | 모드, 시드, 엔딩 ID·계층, 종족·관계 인물 선택, 인과적으로 연결된 후일담, 핵심 지표 | 전체 런 상태 복제, 숨은 미발견 정보 |

실행 기록은 세이브가 아니다. 종료한 런을 다시 진행시키지 않고 결과와 재현 키만 보존한다. 현재 웹 구현은 브라우저 `localStorage`에 최근 20개를 저장하며, 같은 네임스페이스와 시드의 기록은 하나만 유지한다.

## 4. 데이터 기반 종료 계약

`data.run_completion`은 우선순위가 있는 종료 규칙과 반드시 존재하는 대체 결말을 가진다. 코드는 엔딩 ID나 문구를 하드코딩하지 않는다.

```json
{
  "record_namespace": "vespera.preopening.v2",
  "ending_rules": [
    {
      "id": "PREOPENING_COMPLETE",
      "priority": 100,
      "outcome": "COMPLETE",
      "conditions": [
        {"metric": "completed_nights", "operator": "GTE", "value": 5}
      ]
    }
  ],
  "fallback_ending": {"id": "PREOPENING_INCOMPLETE", "outcome": "INCOMPLETE"}
}
```

공통 평가기가 제공하는 지표는 완료 영업 수, 누적 수입·평판, 최종 골드·평판, 수용·거절·취소 손님 수, 보유 개선 수, 긴급 배정 영업 수와 흘려보낸 가능성 수다. 회색 상자 캠페인은 여기에 챕터 허들 실패, 종족 우호도·협약·최고 우호 종족, 몽마 엔딩용 타종족 우호 교류망, 관계 인물 필수 사건 완료 수, 진상 증거와 평화 협약 지표를 추가한다. 존재하지 않는 지표나 지원하지 않는 비교 연산자는 데이터 검증에서 거부한다.

우선순위가 높은 규칙부터 평가하며 첫 일치만 채택한다. 어떤 규칙도 맞지 않으면 대체 결말을 사용하므로 엔딩 화면 없이 런이 끝나는 상태를 허용하지 않는다.

## 5. 현재 구현된 회색 상자 연결

- `src/run.js`: 런 요약, 우선순위형 다단계 종료 규칙 평가, 버전 3 실행 기록, 종족 엔딩의 지배인 선택지, 관계 인물 후일담과 캐릭터 표현 설정 기록
- `src/save.js`: 세이브 스키마 4, 모드별 활성 런, 공용 프로필, 직전 영업 체크포인트, 구버전 쇼케이스 저장 마이그레이션
- `src/state.js`: 캠페인 새 게임 설정, 별도 스토리 장면, 아침·마감 비서 장면, 같은 날 아침 복원, 공용 수첩 지식 합치기와 `FINAL` 진입
- `src/relics.js`: 런 시드·제안 순번으로 격리된 가중 후보 추첨, 보유 전시품과 효과 ID 평가
- `src/data.js`: 기존 v2 데이터를 훼손하지 않고 파생하는 5영업 회색 상자 캠페인, 임시 목표와 여섯 엔딩 계층의 상태 대역
- `data/prototype_v1.json`: 스키마 4의 `PREOPENING_COMPLETE` 종료 조건
- `src/render.js`: 엔딩 ID·결과·기록 ID·브라우저 기록 수, 시나리오 전용 비서 장면과 간접적인 장부 대화 표시
- 정적 검산과 실제 브라우저 회귀: 쇼케이스 5영업, 캠페인 스토리 재개, 공용 전시품 제안·선택·건너뛰기·새로고침 재현·세 효과·재검토 롤백·도감, 2·4일차 챕터 장면, 배드·노말·종족·종족 관계·트루·트루 하렘 우선순위, 후일담, 모드 세이브 격리, 프로필 지식 영속화와 구버전 마이그레이션 확인

이 연결로 기능적 뼈대와 공용 전시품의 첫 종단 경로는 닫혔다. 정식 캠페인의 챕터 수·경제·사건·관계 콘텐츠가 완성되었다는 뜻은 아니며, 다음 코어 작업은 임시 80G 목표를 최종 운영 목표 경제로 교체하고 무한 영업 1시즌을 같은 계약에 연결하는 것이다.

## 6. 사용자 추가 결정 없이 진행할 순서

1. 콘텐츠 누락, 죽은 분기, 도달 불가능 엔딩을 찾는 검산기 추가
2. 최종 운영 목표 경제 시뮬레이션과 임시 80G 목표 교체
3. 무한 영업 1시즌의 감사 목표·폐업·기록 흐름 연결
4. 종족 방향·특화 시설·시너지 변화형 1세트의 데이터 부착 검증
5. 종족·관계 전시품 후보군을 진행 임계 사건에 외부 부착

## 7. 사용자 결정 게이트

아래 결정은 뼈대의 인터페이스는 막지 않지만 임시값을 실제 게임 규칙으로 바꾸기 전에 필요하다.

1. **P0 · 기본 캠페인 운영 목표:** 채무 상환, 목표 자산, 계약 이행 중 무엇을 기본 승리 축으로 삼을지
2. **P0 · 실패의 수위:** 기한 미달이 즉시 폐업인지, 불리한 실패 엔딩·연장 계약을 허용하는지
3. **P1 · 캠페인 슬롯 수:** 가능 세계를 몇 개의 독립 캠페인 슬롯으로 보존할지
4. **P1 · 완전 초기화 범위:** 실행 기록과 운영 수첩까지 지우는 별도 프로필 초기화를 제공할지
5. **P1 · 캠페인 대표 길이:** 기능 검증용 첫 회색 상자 경로를 몇 영업으로 체험시킬지

수치·이름·대사는 위 결정 뒤에도 데이터로 교체할 수 있다. 그 전에는 가칭과 명시적인 임시값을 사용하되 콘텐츠 양을 늘리지 않는다.

## 8. 뼈대 완료 게이트

- 새 게임에서 배드·노말·종족·종족 관계·트루·트루 하렘의 여섯 엔딩 계층에 각각 한 번 실제 도달 가능
- 종료 규칙이 없거나 잘못된 콘텐츠는 시작 전에 검증 실패
- 세이브 후 새로고침·재실행해 같은 시드와 진행 위치 복구
- 엔딩 기록을 두 번 호출해도 중복 생성되지 않음
- 프로필, 캠페인 런, 무한 영업 런의 자원과 관계 상태가 섞이지 않음
- 전시품 도감은 프로필에 남고 보유 패시브는 각 런에만 저장되며, 체크포인트 복원과 새로고침으로 후보를 재추첨하거나 중복 획득할 수 없음
- 임시 종족·인물·장면 묶음을 교체해도 상태 머신과 저장 코드 변경 없음
- 자동 회귀가 새 게임, 저장·불러오기, 여섯 엔딩 계층과 우선순위, 관계 인물 후일담, 기록, 재시작을 모두 통과

이 게이트 전에는 대량 손님·종족·시설·관계 장면과 최종 아트 제작을 우선 작업으로 올리지 않는다.
