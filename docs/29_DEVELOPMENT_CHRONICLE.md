## 1. 목적

이 문서는 완성된 규칙만 기록하는 `99_DECISION_LOG.md`와 달리 게임이 어떤 순서로 만들어졌는지를 추적한다. 사용자 요청, 그 요청을 해석하면서 발견한 충돌, 실제로 추가·수정한 기능과 문서, 검증 결과, 커밋과 남은 작업을 한 흐름으로 남긴다. 차후 제작 방식, 의사결정 패턴, 재작업 원인과 개발 효율을 분석할 때 이 문서를 기준 자료로 사용한다.

## 2. 기록 규칙

### 2.1 앞으로 반드시 기록하는 시점

다음 사건이 발생할 때마다 같은 작업 세션 안에서 이 문서를 갱신한다.

1. 사용자가 새 설정, 수정 의견, 작업 명령 또는 우선순위 변경을 전달했을 때
2. 그 입력이 기존 설정·기능과 충돌해 부정적 피드백이나 사용자 결정 대기가 필요할 때
3. 하나의 구현·문서화·검증·배포 경계 작업을 완료했을 때
4. 작업을 보류·폐기·대체하거나 다른 브랜치로 격리했을 때

### 2.2 항목 형식

신규 항목은 아래 필드를 가능한 범위에서 유지한다.

| 필드 | 기록 내용 |
| --- | --- |
| 입력 | 사용자가 요청하거나 추가한 설정의 요지 |
| 해석·점검 | 기존 설계와의 연결, 모순, 채택하지 않은 해석과 이유 |
| 변경 | 실제로 수정한 시스템·데이터·UI·문서 |
| 검증 | 정적 검사, 브라우저 회귀, 전수조사 또는 사람이 결정해야 할 미검증 항목 |
| 결과 | 완료·진행 중·결정 대기·폐기 상태와 커밋 |
| 다음 | 바로 이어질 작업 또는 사용자 결정 게이트 |

모든 셸 명령과 임시 프로세스를 전사하지는 않는다. 대신 게임의 설계·구현·검증 결과와 브랜치·빌드·배포 경계를 재현할 수 있는 수준으로 기록한다. 원시 변경 내용은 Git 커밋과 해당 산출물이 보존한다.

### 2.3 과거 복원 신뢰도

- `CONFIRMED`: Git 커밋, 현재 파일 또는 결정 로그로 직접 확인했다.
- `RECONSTRUCTED`: 보존된 대화 순서와 문서의 누적 기록을 대조해 복원했다.
- 2026-08-19의 일부 커밋 제목은 `update`, `up4`처럼 포괄적이므로 세부 요청의 정확한 시각은 복원할 수 없다. 이 구간은 결정 로그의 순서와 커밋 파일 목록을 기준으로 묶어서 기록한다.
