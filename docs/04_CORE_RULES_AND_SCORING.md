# 코어 규칙과 점수 체계

- 상태: `v2 IMPLEMENTED`
- 적용 범위: 튜토리얼 + 5영업 압축 쇼케이스
- 목표: 객실 관계, 필수 조건, 선호 사항, 수용·거절, 영업 평가를 구현 가능한 규칙으로 고정한다.

v1의 2영업 최고점과 단일 시설 비교는 검산 이력으로만 보존한다. 현재 권위 규칙은 N/R/SR/SSR, 연박·객실 상태, 시드 제안, 누적 개선을 포함한 v2다.

## 1. 보드 좌표

v2는 3층에 A~D열을 정의한다. A~C의 9개 객실로 시작하고 D열은 수직 증축으로 한 층씩 연다.

- 좌표 형식: `F{층}-{호실}`
- 층: `F1`, `F2`, `F3`
- 호실: `A`, `B`, `C`, `D`
- 예: `F2-B`

호실의 위치 값은 `A=0`, `B=1`, `C=2`, `D=3`으로 계산한다. `F1-D → F2-D → F3-D` 순서의 선행조건을 지키며, 상층만 먼저 살 수 없다.

## 2. 기본 객실 속성

모든 층에서 같은 열은 같은 기본 속성을 가진다.

| 호실 | 기본 속성 | 엘리베이터 거리 | 플레이어 표현 |
|---|---|---:|---|
| A | `noisy` | 0 | 엘리베이터 옆, 시끄러움 |
| B | `quiet` | 1 | 안쪽 객실, 조용함 |
| C | `sunny` | 2 | 큰 창문, 햇빛 |
| D | 증축별 `quiet` 또는 `sunny` | 3 | 새 별관 객실 |

객실 배정 보드와 예약 객실도는 각 층의 A열 왼쪽에 엘리베이터 문을 그린다. 승강기에서 A열로 향하는 작은 소음 파동을 함께 표시해 `엘리베이터 바로 옆 = 기본적으로 시끄러운 객실`이라는 공간 원인을 규칙 설명 전에 읽을 수 있게 한다. 방음 공사로 `noisy`가 제거된 A열은 위치는 그대로지만 객실의 소음 강조 배경이 사라진다.

층 자체는 `floor=1/2/3` 값을 가진다.

## 3. 공간 관계

### 같은 층

두 객실의 층 번호가 같으면 `same_floor`다.

### 이웃 객실

기본적으로 같은 층에서 호실 위치 차이가 1이면 `adjacent`다.

- `F1-A ↔ F1-B`: 이웃
- `F1-A ↔ F1-C`: 이웃 아님
- `F1-B ↔ F2-B`: 이웃 아님

비밀 통로처럼 관계를 바꾸는 시설은 별도의 이웃 관계를 추가할 수 있다.

### 엘리베이터 거리

프로토타입에서는 호실 열로만 계산한다.

- A: 0
- B: 1
- C: 2
- D: 3

층간 이동 비용은 최초 프로토타입의 선호 계산에서 제외한다.

## 4. 배치 기본 규칙

- 한 객실에는 손님 한 명만 배치한다.
- 한 손님은 객실 하나만 사용한다.
- 수용하지 않은 손님은 배치할 수 없다.
- 모든 수용 손님을 배치해야 밤을 마감할 수 있다.
- 하나 이상의 필수 조건이 맞지 않으면 밤을 마감할 수 없다.
- 선호 사항은 충족하지 않아도 영업할 수 있지만 점수를 얻지 못한다.
- 하루 예약 응대 한도는 기본 5명이며, `F1-D → F2-D → F3-D`가 한 실씩 완공될 때마다 1명씩 늘어난다.
- 사용 가능 객실 수는 완공 객실 중 시설로 전환되거나 정비가 필요한 객실을 제외해 별도로 계산한다.

## 5. 조건과 기대의 층

한 손님의 최종 조건과 내부 만족도 항목은 다음 순서로 합쳐진다.

1. 종족 공통 필수 조건과 공통 선호
2. 등급 공통 필수 조건과 공통 선호
3. 카드에 공개되는 개인 선호
4. 결산 뒤 열람되는 종족×등급 숨은 선호
5. 등급이 높을수록 늘어나는 공개 불호와 호텔 격차에 따른 관용

v2에서는 개인에게만 적용되는 필수 조건을 사용하지 않는다. 강한 조건은 종족 또는 등급을 확인해 운영 수첩에서 찾아 적용하고, 손님 카드에는 종족·등급·공개 개인 선호만 표시한다. 아직 만나지 않은 종족·등급의 공개 규정은 `미열람 규칙`으로 표시하며, 첫 신청이 도착하면 열람된다. 등급 규정은 첫 신청 시 자동 열람된다.

숨은 선호는 종족×등급 조합에 속하며 항상 양의 점수를 주는 선택 사항이다. 해당 조합 손님의 투숙 결산 뒤 같은 조합 전체에 열람된다. 숨은 필수 조건, 숨은 감점, 숨은 배정 불가 규칙은 허용하지 않는다.

불호는 필수 조건이 아니다. 불호에 맞는 객실을 배정해도 영업은 성립하지만 내부 만족도가 낮아질 수 있다. 호텔의 예약 시점 평판 단계가 손님 등급보다 충분히 높으면 데이터에 기록된 격차 기준에 따라 일부 불호를 강제로 무시한다. 연박 손님의 기대 기준은 첫 예약 시점으로 고정하고 숙박 도중 오른 평판을 소급 적용하지 않는다.

종족 공통·등급 공통·종족×등급 숨은 선호로 구성되는 공통층에서는 동일 조건을 양수 선호와 불호로 동시에 둘 수 없으며 데이터 로딩을 거부한다. 개인 선호·개인 불호는 공통 성향에서 벗어난 인물 예외를 표현할 수 있도록 이 중복 금지에서 제외하며, 공통층과 겹칠 때도 출처별 항목으로 각각 계산한다.

현재 `PALADIN` 종족 공통층에는 `quiet` 또는 `noisy`를 금지하는 필수 조건이 없다. 성기사 `SR/SSR`의 `ROOM_NOT_HAS noisy`는 등급 공통층에만 속한다. 따라서 같은 직업·종족 표식의 손님이라도 등급이 다르면 소음 필수 조건이 달라질 수 있으며, UI와 결과 원인은 이를 `[종족] / [등급] / [개인]` 출처로 분리한다.

SSR 등급의 세 번째 공통 불호는 `ROOM_HAS sunny`가 아니라 `NEAR_FACILITY LOUNGE`, 즉 `공용 라운지와 가까운 객실`이다. 이 교체로 성기사 종족 공통의 햇빛 객실 선호와 SSR 공통 불호가 같은 조건에서 정면 충돌하지 않는다.

## 6. 최초 규칙 언어

### 필수 조건 연산자

| ID | 의미 | 필요한 값 |
|---|---|---|
| `ROOM_NOT_HAS` | 특정 속성 객실 금지 | `attribute` |
| `MUST_ADJACENT_GUEST` | 특정 손님과 이웃해야 함 | `guest_id` |
| `MUST_SHARE_FLOOR` | 같은 층에 다른 손님이 최소 한 명 있어야 함 | 없음 |

### 선호 사항 연산자

| ID | 의미 | 필요한 값 |
|---|---|---|
| `ROOM_HAS` | 특정 속성 객실 선호 | `attribute`, `points` |
| `ROOM_NOT_HAS` | 특정 속성이 없는 객실 선호 | `attribute`, `points` |
| `FLOOR_IS` | 특정 층 선호 | `floor`, `points` |
| `FLOOR_AT_LEAST` | 일정 층 이상 선호 | `floor`, `points` |
| `ELEVATOR_DISTANCE_AT_LEAST` | 엘리베이터에서 일정 거리 이상 | `distance`, `points` |
| `ELEVATOR_DISTANCE_AT_MOST` | 엘리베이터에서 일정 거리 이하 | `distance`, `points` |
| `ADJACENT_GUEST` | 특정 손님과 이웃 | `guest_id`, `points` |
| `ADJACENT_SPECIES` | 특정 종족과 이웃 | `species_id`, `points` |
| `SAME_FLOOR_SPECIES` | 특정 종족과 같은 층 | `species_id`, `points` |
| `NO_OCCUPIED_ADJACENT` | 이웃 객실을 비워 둠 | `points` |
| `NEAR_FACILITY` | 특정 시설이 있는 칸과 이웃 | `facility_id`, `points` |

프로토타입에서는 조건식의 `AND`, `OR`, 중첩, 부정 조합을 만들지 않는다. 복합 조건은 정식 규칙 엔진 단계에서 추가한다.

`NO_OCCUPIED_ADJACENT`는 SR/SSR의 사생활을 표현하는 고가치 선호다. 이를 필수 조건으로 사용해 증축을 사실상 강제해서는 안 된다.

## 7. 필수 조건 평가

각 필수 조건은 다음 정보를 반환해야 한다.

- 충족 여부
- 영향을 받는 손님
- 원인이 된 객실, 손님 또는 시설
- 플레이어에게 보여줄 한 문장 설명

예시:

`Lady Nox는 조용함을 원한다`가 아니라, 미충족 사유는 `Lady Nox의 옆방은 비어 있어야 합니다. 현재 Lune이 머물고 있습니다.`처럼 원인을 포함한다.

## 8. 선호 점수와 내부 만족도

모든 선호는 조건을 만족하면 정해진 점수를 한 번 준다.

- 한 선호는 여러 이웃이 만족해도 한 번만 계산한다.
- 손님별 점수를 먼저 계산한 뒤 합산한다.
- 시설이 주는 점수는 해당 손님의 선호 항목으로 표시한다.
- 재방문 손님은 직전 만족도 구간에 따라 `+1/+2/+3`의 재방문 보너스를 받는다.
- 종족별 인원 문턱을 넘으면 시너지 점수를, 지정 상극 종족이 같은 층에 있으면 감점을 적용한다. 현재 자동 종족 시너지는 배치된 같은 종족 인원수만 세며 층·인접·공유 공간을 검사하지 않는다.
- 숨은 선호도 발견 전부터 동일하게 계산하지만, 결산 전에는 정체와 상한을 공개하지 않는다.
- 현재 총점과 손님별 점수 구성을 항상 확인할 수 있어야 한다.
- 검산된 최대 만족도는 플레이 UI에 표시하지 않는다.

`공개 선호 점수 = 충족한 선호 + 시설 + 재방문 + 시너지·상극`

손님별 내부 만족도는 공개 선호 점수에 활성 불호, 호텔 격차 첫인상과 객실 청결 경험을 더한 값이다. 청결 점수는 팁을 만드는 공개 선호 점수에는 포함하지 않는다.

`손님 만족도 = 공개 선호 점수 + 호텔 격차 첫인상 - 활성 불호 감점 + 청결 만족도`

| 결산 시 청결도 | 청결 만족도 | 표현 |
|---:|---:|---|
| 90~100 | 0 | 정돈된 객실 |
| 75~89 | -1 | 청소가 필요한 기색 |
| 50~74 | -3 | 눈에 띄게 정돈되지 않은 객실 |
| 0~49 | -6 | 방치된 객실 |

- 정확한 손님 만족도와 호평 기준 숫자는 플레이 UI에 표시하지 않는다.
- 배치 화면에는 기존처럼 선호 점수와 필수 조건 충족 여부를 표시한다.
- 결산에서는 손님별 `호평 / 무난 / 아쉬움` 후기, 주요 원인과 평판 영향만 표시한다.
- 호텔 격차로 무시된 불호는 해당 숙박의 만족도에서 제외한다.
- 오토마타 접객은 중립적으로 보장되므로 직원 태도나 차별을 만족도 변수로 사용하지 않는다.

### 연박 객실 청소 — PROVISIONAL

- 객실 상태는 `{ cleanliness }` 한 축만 사용하며 내구도는 계산·저장하지 않는다.
- `UPGRADE`, 즉 플레이어에게 보이는 `영업 준비 / 공사 계약` 막간에서 지배인은 더러워진 빈 객실과 연박 객실을 모두 선제 청소할 수 있다. 현재 기본 비용은 `8G`이고 청결도를 `100`으로 회복한다.
- 선제 청소하지 않은 실제 더러운 연박 객실만 시드 기반 `35%` 요청 추첨 후보가 된다. 현재 데이터의 `max_per_intermission`은 범위 값이 아니라 정확히 `1`이어야 하며, 같은 손님의 같은 체류에는 최대 1회다.
- 요청 수락은 현재 `8G`, 청결 `100`, 호텔 평판 `+1`이다. 거절은 평판 `-1`, 현재 청결 유지이며 같은 막간에는 해당 객실을 다시 수동 청소할 수 없다.
- 발생률·비용·평판 변화는 `PROVISIONAL`이다. 이 장치만으로 예약 단계의 난도가 해결됐다고 판정하지 않는다.

## 9. 수용과 거절

예약 신청 단계에서 손님별로 `수용` 또는 `거절`을 선택한다.

- 수용하면 기본 숙박비와 만족 시 평판을 얻을 기회가 생긴다.
- 거절하면 즉시 해당 손님의 `reject_reputation`만큼 호텔 평판이 감소한다.
- 수용 후 배치하지 못해 취소하면 `cancel_reputation`만큼 감소한다.
- 취소 손실의 절댓값은 항상 거절 손실보다 커야 한다.
- 수용 인원에는 연박 손님과 사전 확정 손님도 포함되며, 그날의 동적 예약 응대 한도를 넘을 수 없다.
- 수용 인원은 사용 가능 객실 수도 넘을 수 없다. 다만 두 수치 안에 들어도 종족·등급의 필수 숙박 조건을 동시에 만족할 수 있다는 보장은 없으므로, 무리한 수용은 마감 시 긴급 배정과 강제 취소로 이어질 수 있다.

### 현재 예약 압력 감사 — REVISE

과거 고정 시드 전수조사 산출물에서는 신청이 있는 8개 도달 상태 중 전원 수락이 수용 한도상 가능한 7개 상태 모두에 유효 해법이 있었다. 그 7개에서 전원 수락안은 평균 평판과 평균 수입이 모든 유효 부분 수락안 이상이었고, 전원 수락 유효 배치 17,872개 중 음의 평판 배치는 16개였다. 이 감사는 현재 청결 구현을 새로 전수 실행한 결과가 아니며 산출물과 현 소스의 동일성도 증명하지 않는다.

현재 같은 종족 인원 시너지는 위치와 무관하게 자동 발동하므로 많은 손님을 받는 행동에 구조적 보상을 준다. 다음 설계 후보는 시너지에 공간 조건을 요구하고 로비·식당 같은 공개·공유 공간에 경합을 만드는 것이다. 이는 수용 기회비용과 난도를 크게 바꾸므로 사용자 밸런스 결정 전 구현하지 않는다.

## 10. 영업 정산

### 수입

프로토타입은 검산 가능성을 위해 팁의 무작위값을 고정 시드 또는 평균값으로 사용한다.

`총수입 = 수용 손님의 기본 숙박비 합 + 충족한 선호 점수`

선호 점수 1점은 팁 1골드로 환산한다.

### 평판

유효 배치는 평판을 자동으로 주지 않는다.

`평판 변화 = 손님별 후기 영향 합 + 거절 손실 + 취소 손실 + 영업 사이 요청 처리`

- 만족도 0 미만: `아쉬움`, 등급 영향력만큼 음의 평판
- 만족도가 등급별 호평 기준 미만: `무난`, 평판 0
- 만족도가 등급별 호평 기준 이상: `호평`, 등급 영향력만큼 양의 평판
- 등급별 평판 영향력은 `N < R < SR < SSR` 순으로 증가한다.
- 거절과 수용 후 취소는 만족도와 별도의 운영 결정 결과로 유지한다.
- 연박 청소 요청의 수락 `+1` 또는 거절 `-1`은 직전 영업 결과의 `intermissionReputationDelta`와 전체 런 평판 집계에 함께 기록한다.

### 영업 평가 점수

서로 다른 결과를 하나의 등급으로 비교하기 위한 프로토타입 공식이다.

각 손님의 내부 만족도를 해당 등급의 호평 기준으로 정규화하고 평균해 영업 평가를 만든다.

`영업 평가 = 평균 clamp(손님 만족도 / 등급별 호평 기준, -1, 1) × 100`

v2 초기 기준은 50 이상 `좋은 운영`, 80 이상 `훌륭한 운영`이다. 플레이어에게는 숫자보다 평가 문구와 손님별 후기를 우선 표시한다.

## 11. 개선과 시설 규칙

v2의 공사는 한 번 고르고 교체하는 슬롯이 아니라 누적 보유 목록이다. `영업 준비 / 공사 계약` 한 화면에서 `동관 증축`과 `시설·인테리어`를 구분하고, 각 분류에서 영업 사이 최대 1건을 계약한다. 제안은 다음 영업 단계, 평판, 희귀도 확률, 선행조건, 보유 여부를 반영하며 같은 시드에서 재현된다.

| 희귀도 | 시설 |
|---|---|
| N | 방음 객실, 암막 객실 |
| R | 라운지, 서비스 계단 |
| SR | 비밀 통로, 달빛 정원 |
| SSR | 왕실 스위트, 대연회장 |

별도 증축 개선은 `F1-D(N) → F2-D(R) → F3-D(SR)` 순서다. 제안에 증축이 나오지 않거나 구매하지 않아도 유효 수용 부분집합이 남아야 한다.

### v1 시설 원형 보존

아래 세 항목은 v1에서 관계 변경을 검증한 최초 원형이며 v2에서는 누적 시설 풀의 일부로 일반화되었다.

### 방음 객실

- ID: `SOUNDPROOFING`
- 가격: 25골드
- 대상: `F2-A`
- 효과: `noisy` 제거, `quiet` 추가
- 의미: 엘리베이터 가까이를 원하지만 소음 때문에 A열을 쓸 수 없던 Garr에게 전용 해법을 연다.

### 라운지

- ID: `LOUNGE`
- 가격: 30골드
- 위치: `F2-B`
- 효과: 해당 객실은 손님 배치 불가
- 추가 효과: `F2-A`, `F2-C`는 `NEAR_FACILITY(LOUNGE)`를 만족
- 의미: 객실 하나를 포기하고 주변 시설 선호를 강화한다.

### 비밀 통로

- ID: `SECRET_PASSAGE`
- 가격: 35골드
- 연결: `F1-B ↔ F3-C`
- 효과: 두 객실을 `adjacent`로 추가 취급
- 추가 효과: 두 끝 객실의 투숙객은 비밀 이동로 만족으로 각각 `+3`
- 의미: 다른 층의 손님 관계와 점수를 연결해 공개·숨은 이웃 선호의 해법을 바꾼다.

## 12. 등급 기준

### 가능한 배치

- 모든 필수 조건 충족
- 내부 만족도와 평가 점수에 관계없이 영업 가능
- 정상 숙박의 평판 기본값 0

### 좋은 배치

- 손님별 기대 대비 만족도 평균이 50% 이상

### 최고의 배치

- 손님별 기대 대비 만족도 평균이 80% 이상

v1은 검산용 최고점을 데이터에 저장했다. v2도 개발 검증에서는 상한을 사용할 수 있지만 플레이어에게는 현재 만족도 합계만 보여 준다. 정식 버전에서는 생성 문제의 상한 계산기 또는 충분히 검증된 목표값 생성기가 필요하다.

## 13. 공정성 불변 조건

- 신청 목록에는 현재 시설 상태에서 5명 이하의 유효 부분집합이 최소 하나 존재한다.
- 모든 점수와 평판 변화는 결과 화면에서 출처별로 합산된다.
- 내부 만족도 숫자는 숨기되 손님별 후기와 평판 변화의 원인은 결산에서 확인할 수 있다.
- 유효 배치만으로 양의 평판을 주지 않는다.
- 호텔 격차로 불호를 무시하는 기준은 예약 시점에 고정되며 연박 도중 소급 변경하지 않는다.
- 시설은 설명된 공개 효과만 사용한다.
- 숨은 항목은 양수 점수의 종족×등급 숨은 선호만 허용한다. 필수·감점 형태는 데이터 검증에서 거부한다.
- 연박 손님은 첫 배정 객실을 다음 영업에도 유지한다.
- 객실 상태가 기준 미만이어도 확장 구매를 강제하지 않는 유효 수용 부분집합이 최소 하나 있어야 한다.
- 같은 시드, 입력, 수용 목록, 배치, 보유 개선은 항상 같은 결과를 만든다.
