5. 선호 점수와 실시간 증감 표시

10. 최종 결과, 재시작, 웹 빌드

### 5시간 시간 상한

- `0:00~0:25` 프로젝트, 상태 전환, 고정 데이터 로딩
- `0:25~1:40` 객실 배치, 필수 조건 검증, 선호 점수
- `1:40~2:25` 예약 수용·거절, 첫 영업 정산
- `2:25~3:20` 시설 선택과 두 번째 영업 반영
- `3:20~4:05` 원인 표시, 결과 화면, 재시작
- `4:05~4:35` 퍼즐 수치 조정과 전체 흐름 테스트
- `4:35~5:00` 웹 빌드, 배포, 배포본 재검증

### 통과 조건

- 링크를 열어 설명 없이 첫 손님을 배치할 수 있음
- 필수 조건이 맞지 않는 원인을 UI에서 추적할 수 있음
- 첫 영업부터 두 번째 영업까지 진행 차단 버그가 없음
- 시설 선택이 실제 유효 배치 또는 점수 최적해를 바꿈
- 10분 안에 한 세션 완료 가능
- itch.io 또는 동등한 웹 호스팅에서 실행 가능

## 단계 3. 코어 플레이테스트와 방향 판정 — NEXT

### 검증 가설

- 플레이어가 통과점 이후 더 높은 점수를 자발적으로 시도한다.
- 수용·거절 선택을 단순히 최고 등급 선택으로 해결할 수 없다.
- 시설 선택 후 두 번째 퍼즐을 새 문제로 인식한다.
- 점수 및 충돌 원인을 이해한다.
- 한 번 더 플레이할 이유를 말할 수 있다.

### 판정

- PASS: 핵심 판단이 반복되고 개선 시도가 관찰됨
- REVISE: 규칙은 이해하지만 최적화나 경영 선택이 무의미함
- STOP: 배치가 계산 노동으로만 느껴지고 시설이 해법을 바꾸지 못함

PASS 전에는 종족과 시설 콘텐츠를 대량 제작하지 않는다.
