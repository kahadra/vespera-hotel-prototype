# 제출 계획 — 베스페라 호텔 개장 전 초청 영업

- 상태: DRAFT / PUBLIC LINK REQUIRED
- 제출용 제목: `베스페라 호텔`
- 장르 표기: 조건 최적화 호텔 운영 게임
- 예상 플레이 시간: 튜토리얼 제외 12~18분
- 권장 환경: 데스크톱 브라우저, 1280×720 이상

## 1. 제출 전략

제출본은 튜토리얼과 5회의 **개장 전 초청 영업**으로 구성한다. 이는 정식 게임에서 5일 만에 최종 등급까지 영구 해금된다는 뜻이 아니라, 짧은 심사 시간 안에 장기 성장 구조의 각 층위를 실제 플레이로 확인시키기 위한 별도 진행 규칙이다.

- 시간 제한 없는 2인 배치 연습과 건너뛰기
- 첫 영업부터 적용되는 2분 체크인 마감과 재배치 5초 비용
- N으로 시작해 평판에 따라 R·SR·SSR 등장 확률이 변하는 손님과 공사 제안
- 매번 달라지는 손님·공사 후보와 동일 시드 재현
- 수용·거절, 숙박비, 평판, 연박과 객실 상태 영향을 함께 비교하는 예약 판단
- 한 영업 준비 화면의 `동관 증축`과 `시설·인테리어` 두 구획에서 각각 최대 1건 계약
- F1-D → F2-D → F3-D 순서를 지키는 동관 증축
- 증축 객실 수에 따라 5→6→7→8명으로 늘어나는 예약 응대 한도와 별도 사용 가능 객실 수
- 예약 단계에서 확인하는 연박 고정 객실도와, 인원 여유가 있어도 필수 조건 조합 때문에 실패할 수 있는 과수용 위험
- 실제 투숙 인원과 연박 손님을 반영하는 종족 시너지·상극
- 청결·내구도·객실 가용 상태가 다음 영업으로 이어지는 호텔 상태
- 처음 숙박한 종족×등급 조합의 추가 점수 조건을 정산 뒤 `숨은 선호`로 열람
- 다섯 번째 영업의 시연용 SSR 왕실 특별 초청

### 진행 속도 고지

제출 영상에서는 00:06~00:15 진행 속도 안내에서만 다음 사실을 한 번 표시한다. 왕실 손님 카드, 해당 장면 자막, 최종 결과와 엔드 카드에는 같은 안내를 반복하지 않는다.

> 정식 게임의 장기 성장 구조를 5회 영업으로 압축했습니다. 5번째 영업의 SSR은 영구 해금이 아닌 시연용 특별 초청입니다.

정식 게임에서는 등급과 공사 후보를 여러 챕터와 런에 걸쳐 점진적으로 발견하며, 정확한 등장 시점과 확률 곡선은 별도 플레이테스트로 조정한다.

## 2. 플레이 링크 제출

### 대표 링크: GitHub Pages 또는 itch.io HTML5 페이지

업로드 파일은 정적 빌드 ZIP 또는 저장소 루트의 `index.html`이다.

- 브라우저 안에서 즉시 실행
- 1280×720 기준
- 로그인, 비밀번호, 승인 요청 없음
- 심사 기간 동안 접속 가능
- 별도 Python 설치나 로컬 서버 실행 안내를 제출 링크에 요구하지 않음

### 링크 옆 조작 안내

아래 문구를 사용한다.

> 손님 카드를 클릭하면 정보만 열람하고, 객실 배정·교환·해제는 카드를 객실 또는 대기 명단으로 드래그해 진행합니다. 시간 제한 없는 튜토리얼은 건너뛸 수 있습니다. 실제 영업은 회차마다 2분이며 이미 배치한 손님을 옮길 때마다 5초가 줄어듭니다. 운영 수첩을 연 동안에는 시간이 멈춥니다. 이 제출본에서는 다섯 번의 개장 전 초청 영업으로 장기 성장 구조를 미리 체험합니다.

## 3. 제출용 게임 소개

### 한 문장

종족과 등급별 숙박 규칙을 익히고 손님·공사·객실을 선택해, 매 영업의 객실 배정과 호텔의 장기 상태를 함께 최적화하는 판타지 호텔 운영 게임.

### 짧은 소개

> 베스페라 호텔의 지배인이 되어 서로 다른 종족과 등급의 손님을 맞이하세요. 모든 손님에게 적용되는 필수 규칙을 먼저 지킨 뒤 개인 선호, 정산 뒤 밝혀지는 숨은 선호, 종족 시너지와 상극을 비교해 더 나은 객실 배정을 찾아야 합니다. 번 돈으로 계약한 동관 증축과 시설·인테리어, 연박 손님이 남긴 청결·내구도 변화가 다음 영업의 운영 조건을 바꿉니다. 제출용 프로토타입은 이 장기 성장 구조를 다섯 번의 개장 전 초청 영업에 담았습니다.

### 핵심 특징

- 전문 용어 없이 체험하는 필수 규칙 만족과 점수 최적화
- 무제한 튜토리얼 뒤 2분 영업에서 관리하는 판단 시간과 수정 비용
- 현재 만족도만 보여주고 가능한 최고점은 숨기는 배치 평가
- 평판에 따라 N·R·SR·SSR 확률이 0%부터 변하는 손님·공사 제안
- 손님 거절 손실과 동관 증축·시설 인테리어 투자 사이의 경영 선택
- 예약 응대 한도, 사용 가능 객실, 연박 고정 위치를 함께 보고 결정하는 과수용 위험
- 영업 준비에서 두 공사 구획별 최대 1건을 계약하는 선택 제한
- 객실 청결·내구도, 손님 연박, 종족 시너지·상극의 누적
- 처음 만난 종족·등급의 공개 규정은 `미열람 규칙`에서 열람 상태로 전환
- 종족×등급의 추가 점수 조건은 첫 숙박 정산 뒤 `숨은 선호`로 열람

## 4. 용어 기준

서로 다른 두 정보가 섞이지 않도록 다음 표현을 고정한다.

| 게임 내 표현 | 의미 | 사용하지 않을 표현 |
|---|---|---|
| 미열람 규칙 | 아직 만나지 않은 종족 또는 등급의 공개 규정 전체. 필수 숙박 조건과 공통 선호를 함께 포함 | 잠긴 금기, 미해금 필수 조건 |
| 숨은 선호 | 해당 종족×등급 손님의 첫 숙박 정산 뒤 밝혀지는 추가 점수 조건 | 숨은 필수 조건, 비공개 금기 |
| 왕실 특별 초청 | 5번째 영업에서 SSR의 위험과 보상을 보여주기 위한 특별 제안 | 5일 만의 SSR 영구 해금 |

## 6. Codex 활용 설명

### 01. Codex를 어디에 사용했나요?

> 게임 규칙 문서화, 데이터 구조 설계, 정적 웹 프로토타입 구현, 5회 진행과 시드 기반 제안 설계, 규칙·점수 검산, Edge 자동 플레이 테스트, 반응형 UI 수정, 제출 영상 자동화와 배포 검증에 Codex를 활용했습니다.

### 02. 어떤 기능을 구현했나요?

> 시간 제한 없는 튜토리얼과 건너뛰기, 5회의 2분 영업, 재배치 시간 비용과 마감 시 긴급 배정, N·R·SR·SSR 손님·공사 후보, 평판별 확률과 시드 기반 제안, 손님 수용·거절, 증축에 따라 늘어나는 예약 응대 한도와 별도 사용 가능 객실 수, 연박 객실도, 동관 증축과 시설·인테리어 계약, 객실 청결·내구도, 종족 시너지·상극, 운영 수첩의 미열람 규칙과 정산 뒤 숨은 선호 열람, 시연용 SSR 특별 초청과 최종 결과를 구현했습니다.

### 03. 어떤 문제를 해결했나요?

> 알고리즘 용어를 호텔 운영의 자연스러운 표현으로 바꾸고, 공개 규정과 플레이로 발견하는 추가 점수 조건이 UI에서 섞이던 문제를 운영 수첩과 손님 카드로 분리했습니다. 만나지 않은 종족·등급의 필수 숙박 조건과 공통 선호 전체는 미열람 규칙, 첫 숙박 정산 뒤 알게 되는 종족×등급 추가 점수는 숨은 선호로 구분했습니다. 튜토리얼과 시간제 실전을 분리하고, 무제한 재배치를 수정 비용으로 제한했습니다. 또한 5회 만에 SSR까지 등장하는 이유를 개장 전 초청 영업이라는 별도 진행 형식과 시작 안내로 구분했습니다.

### 04. 사람이 직접 결정한 부분은 무엇인가요?

> 호텔 경영이라는 주제, 전문 용어를 직접 노출하지 않는 방향, 필수 규칙과 선호의 정보 구조, 베스페라 호텔이라는 이름, 손님 수용·거절과 객실 상태의 경영 의미, 개장 전 초청 영업 5회 구성과 정식 성장 밸런스의 분리는 사람이 직접 결정했습니다. Codex의 제안과 구현 결과는 사람이 반복해서 검토하고 수정 방향을 정했습니다.

### 기존 프로젝트 관련 기재

제출 전 실제 개발 이력을 사용자가 확인해 다음 중 하나를 선택한다.

- 전부 신규라면: `본 프로젝트의 기획, 규칙, UI, 코드와 검산 도구는 챌린지 기간 동안 새로 제작했습니다.`
- 기존 기반이 있다면: `기존에 보유한 [기반 요소]를 사용했으며, 챌린지 기간 동안 [신규 규칙·UI·코드·콘텐츠]를 새로 제작했습니다.`

확인하지 않은 개발 시점을 임의로 기재하지 않는다.
