# 제출 계획 — 베스페라 호텔: 첫 영업

- 상태: DRAFT / PUBLIC LINK AND VIDEO REQUIRED
- 제출용 제목: `베스페라 호텔: 첫 영업`
- 장르 표기: 조건 최적화 호텔 경영 퍼즐
- 예상 플레이 시간: 5~8분
- 권장 환경: 데스크톱 브라우저, 1280×720 이상

## 1. 제출 전략

제출본은 현재 검증된 2영업 세로 단면으로 고정한다.

- 첫 영업 객실 배치
- 종족·등급 공통 규칙을 확인하는 운영 수첩
- 개인 선호 점수 최적화
- 첫 영업 정산과 시설 선택
- 손님 수용·거절
- 시설과 명단이 바꾼 두 번째 배치
- 최종 수입·평판·평가

청결도, 내구도, 연박은 다음 프로토타입의 확정 방향이지만 현재 제출 설명의 구현 기능에는 포함하지 않는다. 마감 전 새 시스템을 추가해 검증된 전체 흐름을 흔들지 않는다.

## 2. 플레이 링크 제출

### 1차: itch.io HTML5 페이지

업로드 파일:

`build/vespera-hotel-prototype.zip`

설정 기준:

- 프로젝트 형식: HTML Game
- 브라우저 내 실행
- 화면 기준: 1280×720
- 전체 화면 버튼 허용
- 다운로드 전용이 아니라 페이지에서 즉시 플레이
- 심사 기간 동안 페이지와 게임을 계속 접근 가능 상태로 유지
- 로그인, 비밀번호, 승인 요청 없음

itch.io는 ZIP 루트의 `index.html`을 진입점으로 사용하는 HTML 게임 업로드를 공식 지원한다. 현재 배포 ZIP은 이 구조를 이미 만족한다.

### 2차: GitHub Pages 비상 링크

itch.io 임베드나 업로드 처리에 문제가 생길 때 같은 정적 파일을 GitHub Pages에 게시한다. 제출란에는 하나의 대표 링크만 쓰되, 제출 메모와 내부 체크리스트에는 비상 링크를 보관한다.

### 링크 옆 조작 안내

아래 문구를 그대로 사용한다.

> 마우스로 손님을 선택한 뒤 객실을 선택하거나, 손님을 객실로 드래그하세요. 이미 배치된 손님끼리는 객실을 맞바꿀 수 있습니다. 상단의 운영 수첩에서 호텔·종족·등급 규칙을 언제든 확인할 수 있습니다. 한 세션은 약 5~8분입니다.

## 3. 제출용 게임 소개

### 한 문장

종족과 등급별 숙박 규칙을 수첩에서 익히고, 받을 손님과 객실을 선택해 가장 가치 높은 밤을 만드는 호텔 경영 퍼즐.

### 짧은 소개

> 베스페라 호텔의 새 지배인이 되어 판타지 손님들의 첫 영업을 준비하세요. 모든 손님에게 공통으로 적용되는 종족·등급 규칙을 먼저 만족시킨 뒤, 서로 충돌하는 개인 선호를 비교해 더 높은 수입과 평가를 만들어야 합니다. 첫날 벌어들인 돈으로 선택한 시설과 거절한 손님이 두 번째 밤의 해법을 바꿉니다.

### 핵심 특징

- 전문 용어 없이 체험하는 조건 만족과 점수 최적화
- 종족·등급 규칙이 진행에 따라 기록되는 운영 수첩
- 정답 통과 뒤에도 다시 배치할 이유를 만드는 개인 선호 점수
- 수용·거절의 평판 손실과 객실 공간을 함께 비교하는 예약 판단
- 방음 객실, 라운지, 비밀 통로가 만드는 서로 다른 두 번째 해법

## 4. 3분 플레이 영상 구성

목표 길이는 2분 40초~2분 55초로 잡아 업로드 인코딩이나 앞뒤 여백이 있어도 3분을 넘지 않게 한다.

| 시간 | 화면 | 전달할 내용 |
|---|---|---|
| 0:00~0:12 | 초대장 화면 | 제목과 한 문장 소개 |
| 0:12~0:30 | 운영 수첩의 종족·잠긴 귀빈 규정 | 공통 규칙 학습과 해금 구조 |
| 0:30~1:00 | 첫 영업 배치 | 필수 규칙과 개인 선호의 차이, 실시간 점수 |
| 1:00~1:15 | 첫 영업 결과 | 수입·평판·평가 정산 |
| 1:15~1:32 | 시설 선택 | 시설이 다음 문제의 객실 관계를 바꿈 |
| 1:32~1:55 | 손님 수용·거절 | 높은 숙박비와 공간 비용 비교 |
| 1:55~2:12 | 해금된 귀빈 수첩 | 같은 등급에 공통 규칙이 적용됨 |
| 2:12~2:38 | 두 번째 배치 | 비밀 통로 또는 라운지로 달라진 해법 |
| 2:38~2:50 | 최종 결과 | 한 세션 완결과 재도전 가능성 |

### 영상 제작 기준

- 실제 브라우저 플레이만 사용
- 1280×720 또는 1920×1080, 30fps
- 커서 표시
- 로딩, 실수 복구, 긴 고민 구간은 편집
- 자막으로 `공통 규칙`, `개인 선호`, `수용·거절`, `시설로 바뀐 해법` 표시
- 배경 음악보다 조작과 설명 전달을 우선
- 미래 계획인 청결·내구도·연박 화면이나 문구는 넣지 않음

## 5. Codex 활용 설명

### 01. Codex를 어디에 사용했나요?

> 게임 규칙 문서화, 데이터 구조 설계, 정적 웹 프로토타입 구현, Python 전수 검산기 작성, Edge 자동 플레이 테스트, 반응형 UI 수정과 배포 ZIP 검증에 Codex를 활용했습니다.

### 02. 어떤 기능을 구현했나요?

> 3×3 객실 배치, 종족·등급 공통 조건 평가, 개인 선호 점수, 운영 수첩의 잠금·해금, 예약 수용·거절, 수입·평판 정산, 시설 세 종류, 두 번째 영업과 최종 결과 화면을 구현했습니다.

### 03. 어떤 문제를 해결했나요?

> 알고리즘 용어를 호텔의 자연스러운 언어로 바꾸고, 공통 규칙과 개인 선호가 UI에서 섞이던 문제를 수첩과 손님 카드로 분리했습니다. 가능한 모든 배치를 Python으로 열거해 시설별 최고점을 검증했고, 브라우저 자동 플레이로 계산 결과와 실제 화면 흐름이 일치하는지 확인했습니다. 1024px 화면에서 깨진 헤더와 과도하게 커진 손님 카드도 캡처 기반으로 수정했습니다.

### 04. 사람이 직접 결정한 부분은 무엇인가요?

> 장르와 핵심 재미, 호텔 경영이라는 주제, CSP를 전문 용어 없이 표현하는 방향, `금기`라는 표현의 폐기, 베스페라 호텔이라는 이름, 손님 카드와 운영 수첩의 정보 분리, 어떤 기능을 제출 범위에서 제외할지는 사람이 직접 판단했습니다. Codex의 제안과 구현 결과를 사람이 반복해서 검토하고 수정 방향을 결정했습니다.

## 6. 기존 프로젝트 관련 기재

제출 안내는 기존 프로젝트 사용을 허용하지만, 챌린지 기간 동안 새로 개발한 내용을 명시하도록 요구한다.

제출 전 아래 사실을 사용자가 확인해 하나를 선택한다.

- 전부 신규라면: `본 프로젝트의 기획, 규칙, UI, 코드와 검산 도구는 챌린지 기간 동안 새로 제작했습니다.`
- 기존 기반이 있다면: `기존에 보유한 [기반 요소]를 사용했으며, 챌린지 기간 동안 [신규 규칙·UI·코드·콘텐츠]를 새로 제작했습니다.`

확인하지 않은 개발 시점을 임의로 기재하지 않는다.
