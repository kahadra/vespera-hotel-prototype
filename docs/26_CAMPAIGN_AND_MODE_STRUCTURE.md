# 시나리오 캠페인과 무한 영업 구조

- 상태: `PROPOSED · THREE-MODE DESKTOP ROUTING / FINANCE KERNEL CONFORMANCE PASS`
- 적용 범위: 정식판의 모드, 캠페인 시간축, 종족·관계 인물 분기, 성별 선택, 엔딩과 세이브 경계
- 비적용 범위: 현재 v2 5회 개장 전 초청 영업의 내부 규칙과 수치. 다만 개발본의 모드 진입·저장 경계는 이 문서의 회색 상자 검증 대상으로 사용한다.

이 문서는 정식판의 전체 플레이 구조를 소유한다. 구체적인 종족 규칙과 시너지 계산은 `25_SPECIES_AND_SYNERGY_SYSTEM.md`, 영구 지식과 UI는 `27_OPERATIONS_HANDBOOK.md`, 제작 순서와 통과 조건은 `02_PRODUCTION_ROADMAP.md`를 따른다.

## 1. 두 모드의 역할

| 구분 | 시나리오 캠페인 | 무한 영업 |
| --- | --- | --- |
| 중심 경험 | 종족·인물·운영 방향 선택과 여러 엔딩 | 객실 배정·시설·아이템 빌드와 생존 기록 |
| 콘텐츠 구성 | 제작된 공통 흐름, 조건부 종족 영업, 별도 사건 장면 | 시드 기반 신청·공사·계약과 시즌 변형 |
| 길이 | 경로에 따라 달라지는 유한 캠페인 | 평판 감사에 실패할 때까지 지속 |
| 평판 역할 | 시장·시나리오·협약·엔딩 조건 | 콘텐츠 해금과 시즌 생존 판정 |
| 실패 | 운영 목표 실패 또는 제한된 결말 | 감사 미달 시 호텔 폐업과 런 종료 |
| 반복 이유 | 다른 종족 방향, 관계와 엔딩 | 다른 시드, 시설·아이템 조합과 최고 생존 기록 |

시나리오를 100~200개의 선형 영업으로 늘리지 않는다. 캠페인은 서사적 완결과 선택 결과를 담당하고, 장기 반복 운영은 무한 영업이 담당한다.

### 현재 데스크톱 시작 라우팅

- Electron을 queryless로 실행하면 `시나리오 캠페인 / 무한 영업 / 초청 영업` 세 모드 허브가 먼저 열린다. 브라우저 queryless 주소는 공개 쇼케이스와 기존 회귀를 위해 계속 `SHOWCASE`로 시작한다.
- 모드 선택은 각각 `?mode=campaign`, `?mode=endless`, `?mode=showcase`의 새 문서로 이동하며 다른 모드의 활성 저장을 지우지 않는다.
- 허브 복귀는 진행 중 우발 이탈을 만들지 않도록 각 모드의 `TITLE`과 `FINAL`에서만 제공한다. 앱을 다시 실행하면 항상 queryless 허브에서 시작하고, 저장이 있는 모드의 타이틀에서 정확히 이어간다.
- 현재 허브의 캠페인과 무한 영업 설명은 5영업 `GREYBOX`를 가리킨다. 합성 `FORMAL_CAMPAIGN`의 56/70일 계약은 URL이나 허브에 플레이 모드로 노출하지 않는다.

### 새 게임의 성별 설정

정식 캠페인의 플레이어는 인간 지배인으로 고정한다. 새 게임에서는 플레이어와 표준 관계 인물의 성별 표현을 정하며, 기존 문서의 `히로인`은 이후 성별 선택이 가능한 `관계 인물`로 통칭한다. 플레이어 종족은 선택값이나 세이브 변수가 아니다.

| 설정 | 기본값 | 선택지 | 적용 범위 |
| --- | --- | --- | --- |
| 플레이어 종족 | 인간 | 선택 없음 | 지배인 역할과 세계관에서 고정 |
| 플레이어 성별 | 남성 | 남성 / 여성 | 플레이어 호칭·대명사·자기표현과 명시적으로 작성된 일부 대화·선호·사건 |
| 관계 인물 성별 프리셋 | 여성 5명 | 전원 여성 / 남성 중심 / 역할별 개별 선택 | 이름·외형·호칭·초상·도트·일부 배경 설정과 개인 장면 |
| 비서 오토마타 외형 | 선택 필요 | 남성형 / 여성형 | 초상·음성·호칭 표현만 변경, 역할과 기능은 동일 |

- 플레이어 성별과 관계 인물 성별은 서로 독립적으로 선택한다. 플레이어 성별만으로 호텔 운영 수치, 조사 협력, 호감도, 관계 가능 여부나 보상을 자동 변경하지 않는다. 설정상 인과가 있는 개별 손님의 대화·선호와 사건은 이 값을 명시적으로 참조할 수 있다.
- `남성 중심`에서는 인족·뱀파이어·늑대인간·몽마 관계 인물을 남성으로 두고 마녀 관계 인물은 여성으로 유지한다.
- `역할별 개별 선택`에서는 공개된 우호·중립 관계 인물 슬롯마다 남성 또는 여성을 정하되 마녀는 여성으로 잠근다. 숨은 적대 인물이나 미공개 관계선을 선택 화면에서 누설하지 않는다.
- 선택은 캠페인 세이브를 만든 뒤 고정한다. 진행 중 변경으로 이름·초상·회상 기록이 뒤섞이지 않게 하며, 다른 조합은 새 캠페인에서 선택한다.
- 성별 변형은 시나리오 역할, 핵심 성격, 종족 사건의 원인, 조사 기능, 관계 조건과 결말의 의미를 바꾸지 않는다.
- 변형 가능한 부분은 이름, 외형, 호칭, 사회적 기대, 가족·공동체와의 관계, 일부 과거 경험, 대사와 장면 연출이다. 같은 문장에 호칭만 치환하는 수준으로 끝내지 않되 완전히 별개의 시나리오 두 개로 분기하지도 않는다.
- 몽마 관계 인물은 여성형에서 서큐버스, 남성형에서 인큐버스 계통으로 표시한다. 꿈·계약·전환 출신이라는 핵심 역할과 퍼즐 기능은 동일하다.
- 마녀는 여성만 존재하므로 마녀 관계 인물은 항상 여성이다. 남성형 이름·초상·도트·개인 장면은 제작하지 않는다.
- 정식판 일반 손님은 선택적 성별 정보를 가질 수 있다. 성별만으로 공통 만족도·평판·시너지 보정을 만들지 않고, 개별 손님·문화·사건에 원인이 있을 때만 선호·불호와 조건에서 참조한다.
- 성별 기반 하드 제약은 안전·종교·계약처럼 강한 이유가 있을 때 예약 단계에서 공개한다. 그 밖의 조건은 기본적으로 소프트 선호로 사용한다.
- 몽마의 성별, 성적 지향과 꿈·정기 적합성은 서로 독립된 속성으로 취급한다.
- 캠페인에서 성별별 이름·외형·초상·도트와 세부 서사를 제작하는 인물은 표준 관계 인물 5명이며, 비서 오토마타는 세부 서사 분기 없이 남성형·여성형 표현 자산만 별도로 가진다.
- 비서 오토마타는 일반 손님이나 표준 관계 인물 5명에 포함하지 않는 인공 종족의 고정 운영 보조 역할이다. 외형 선택은 별도로 저장하며 관계·로맨스·일반 투숙 종족 규칙과 교차하지 않는다.
- 내부 데이터는 공통 `character_role_id` 아래 허용된 `MALE`과 `FEMALE` 표현 변형을 두고, 진행 플래그·호감도·조사 신뢰·엔딩 조건은 역할 ID를 기준으로 저장한다. 마녀 역할은 `FEMALE` 변형만 가진다.

```json
{
  "player_gender": "MALE",
  "relationship_gender_preset": "ALL_FEMALE",
  "relationship_character_gender_by_role": {
    "RELATIONSHIP_HUMAN": "FEMALE",
    "RELATIONSHIP_VAMPIRE": "FEMALE",
    "RELATIONSHIP_WEREWOLF": "FEMALE",
    "RELATIONSHIP_WITCH": "FEMALE",
    "RELATIONSHIP_DREAM_DEMON": "FEMALE"
  }
}
```

`relationship_gender_preset`은 `ALL_FEMALE`, `MALE_CENTERED`, `PER_ROLE` 중 하나다. `MALE_CENTERED`와 `PER_ROLE`에서도 `RELATIONSHIP_WITCH`는 항상 `FEMALE`로 검증한다. 프리셋을 선택해도 최종 저장은 관계 인물 역할별 값으로 펼쳐 두어 세이브 마이그레이션과 회상 재생에서 같은 인물을 재현한다. 일반 손님의 선택적 성별 필드는 이 프리셋과 분리하며 구현 시 손님 데이터 규격에서 정의한다. 내부 ID는 가칭이며 구현 착수 시 데이터 명명 규칙에 맞춰 확정한다.

`secretary_automata_presentation`은 `MALE` 또는 `FEMALE`이며 캠페인 생성 뒤 고정한다. 어느 값을 골라도 같은 장면 ID와 상태 전환을 사용하고 표현 자산만 교체한다.

## 2. 콘텐츠 시간 단위

| 단위 | 정의 | 캠페인 영업 기한 | 별도 장면 시간 |
| --- | --- | --- | --- |
| 일반 영업 | 예약·배치·정산·공사로 이어지는 기본 운영 | 소모 | 없음 |
| 사건 영업 | 종족·시설·조사 규칙이 적용된 특수 운영 | 소모 | 전후 장면 가능 |
| 종족 에피소드 | 갈등, 선택, 협약과 결과를 다루는 장면 | 직접 소모하지 않음 | 소모 |
| 관계 인물 장면 | 개인 관계와 감정적 선택 | 직접 소모하지 않음 | 자유시간 슬롯 소모 |
| 메인 장면 | 챕터 도입·전환·결산 | 소모하지 않음 | 소모 |
| 숨은 조사 장면 | 여러 종족 사건의 증거 연결 | 소모하지 않음 | 숨은 분기에서만 발생 |

대화 장면을 객실 배정 없는 가짜 스테이지로 세지 않는다. 종족 에피소드의 기본 리듬은 `발단 장면 → 사건 영업 → 결과·방향 선택 장면`이다.

메인·종족 장면과 관계 인물 장면은 같은 선택 자원을 사용하지 않는다. 종족 사건을 해결하느라 개인 관계를 볼 수 없거나, 개인 관계를 보느라 캠페인의 필수 진상을 놓치는 구조를 기본값으로 두지 않는다.

### 압축 운영 달력과 하루 일정 설명자

정식 캠페인에서 `스테이지 1개 = 달력 하루 1일 = 영업 1회`다. 아침 브리핑, 정산 마감과 그날의 전후 사건 장면은 같은 스테이지 안에서 처리하며 별도 영업일을 추가로 소모하지 않는다.

이 달력은 현실의 12개월·365일 역법을 축소 복제하지 않는다. 제작·경제 시뮬레이션용 `PROVISIONAL` 기준에서 본편의 압축 1년은 `4계절 × 14일 = 56스테이지`다. 계절 하나는 2주이며 `평일 10일·주말 4일`로 구성한다. 7스테이지를 1주로 보고 6·7일차를 주말로 지정한다. 트루 분기는 기존 56일 경계를 뒤로 미루지 않고 같은 길이의 추가 계절 14일을 이어 총 70스테이지로 진행한다. 이 수치는 콘텐츠 밀도 검증 뒤 조정할 수 있다.

각 영업일은 고정 시나리오 배열의 순번이 아니라 `하루 일정 설명자`로 구성한다.

| 설명자 요소 | 책임 |
| --- | --- |
| 스테이지·하루 인덱스 | 진행 위치와 남은 기한 계산 |
| 계절 ID와 계절 내 위치 | 계절 구간의 수요 변형과 사건 자격 |
| 주차·요일 | 7일 주기 표시와 6·7일차 주말 여부 |
| 공휴일·특별 행사일 태그 | 특정 스테이지 또는 계절 내 위치에 배치되는 당일 변형 |
| 시나리오·규칙 참조 | 챕터·선택·사건 조건에 맞는 당일 운영 규칙 |
| 수요 변형 참조 | 신청 손님 수, 등급 분포와 종족 후보 풀 변경 |

시나리오는 날짜 그 자체가 아니라 하루 일정 설명자가 참조하는 재사용 가능한 템플릿이다. 챕터 사건, 계절, 주말, 공휴일과 특별 행사일의 변형을 합성해 그날의 손님 수·등급·종족 풀을 결정하며, 코드에 `1일차 시나리오`, `2일차 시나리오`처럼 고정 배열로 박지 않는다. 같은 시드와 진행 상태에서는 같은 하루 일정이 복원되어야 하고, 당일 수요 변형은 예약을 받기 전에 브리핑에서 공개한다.

현재 5영업 배열은 상태 전환과 엔딩을 검증하는 `GREYBOX` 종단 fixture다. 하루 수입 규모를 가늠하는 참고 자료로는 사용할 수 있지만 정식 캠페인의 총 기간, 부채 원금, 유지비나 상환 가능성을 정하는 경제 표본으로 확대하지 않는다.

### 시나리오 전용 하루 개시와 마감 장면

```text
DAY_OPENING
→ 비서 오토마타의 예약·객실 브리핑과 당일 시나리오
→ 예약 → 배치 → 정산
→ RESULT_REVIEW 마감 보고
→ 마감 서명: 다음 진행
  또는 아침 장부 재열람: 같은 DAY_OPENING
```

아침 브리핑은 별도 시간이나 영업 횟수를 소모하지 않는다. 당일 사건 조건, 이전 선택에 따른 대사와 운영 주의점을 전달하는 시나리오 장면이다. 마감 보고에서 기능명이나 세계관 원리를 설명하지 않고, 지배인이 비서에게 아침 장부를 다시 읽어 달라고 요청하는 대화만 제공한다. 같은 날을 반복한 뒤 비서가 처음 펼친 장부에 기시감을 느끼거나 지배인이 다음 내용을 미리 아는 정황으로 단서를 축적한다.

비서와 아침·마감 대화를 거치는 절차는 시나리오 캠페인에만 적용한다. 무한 영업은 반복 속도를 위해 이 장면을 생략하지만 정산에 `이번 영업 다시` 버튼을 직접 제공한다. 이 기능에는 예지, 세계선이나 다른 서사적 해석을 붙이지 않는다. 현재 `SHOWCASE` 초청 영업은 심사 흐름을 위해 재시도 UI를 표시하지 않는다.

## 3. 캠페인 볼륨과 경로

본편은 공개 5개 챕터로 56일 경계까지 진행한다. 봄을 두 개의 7일 챕터로 나누고 여름·가을·겨울을 각각 14일 챕터로 배정해 5챕터와 4계절을 함께 유지한다. 트루 분기의 추가 계절은 공개 본편을 늘리지 않는 숨은 챕터 6이며 day 70에 끝난다.

| 경로 | `PROVISIONAL` 영업일 | 역할 |
| --- | ---: | --- |
| 본편 | 56 | 압축 1년의 기본 경영, 종족·관계 진행과 56일 결산 |
| 트루 분기 | 70 | day 56 부채 해결 뒤 추가 계절 14일의 숨은 CH6 조사·결전과 최종 결산 |

`56/70일`은 제작과 경제 시뮬레이션을 시작하기 위한 기준이며 정식 고정값이 아니다. 대표 레벨의 판단이 반복되거나 사건·관계 장면의 밀도가 부족하면 콘텐츠 밀도 검증 결과에 따라 조정한다. 트루 분량을 조정하더라도 본편 경계와 추가 계절을 분리하는 구조를 먼저 유지한다.

진행 권위 계약은 모든 스테이지를 정상 영업일로 기록하고, 56일 완료 뒤 정확한 gate 증거가 있을 때만 57일을 연다. 합성 `FORMAL_CAMPAIGN` 데이터에서는 이 권위를 상태·결과·세이브·재시도·실행 기록에 연결해 56/70일 종단을 검증한다. 현재 다섯 개 회색 상자 시나리오를 나머지 연산으로 순환하는 계획은 저장·결과 덮어쓰기 방지 검증용일 뿐 정식 영업 콘텐츠가 아니다. 생성기 또는 검증된 명시 계획 없이 이 순환을 URL이나 데이터 로더의 플레이 가능한 정식 56일 모드로 노출하지 않는다.

## 6. 종족 방향과 난도

| 방향 | 운영 특성 | 보상 | 장기 영향 |
| --- | --- | --- | --- |
| 전문화 | 다른 종족을 배제하거나 층을 분리해 해법 단순화 | 자종족 시설·수입·희귀 손님 강화 | 특정 종족 결말에 유리, 연합 조사 비용 증가 |
| 실리적 중재 | 선택한 일부 집단만 협력 | 제한된 혼합 시너지와 관리 가능한 위험 | 기본·관계 경로 모두 가능 |
| 화합 | 여러 종족의 시설·인원·공간 조건을 동시에 관리 | 높은 점수 상한, 공동 시설·손님·연합 신뢰 | 최고난도 경로 접근 비용 감소 |

전문화는 낮은 가치의 나쁜 선택이 아니다. 안정 운영과 특정 종족·관계 엔딩을 위한 합리적인 해법이다. 화합은 기존 상극을 무료로 제거하지 않고, 복합 조건을 만족했을 때만 높은 보상으로 반전한다.

전문화 선택 하나가 숨은 최고난도 경로를 즉시 영구 봉쇄하지 않는다. 대신 늦은 화해 영업, 시설 철거·재건, 종족 평판 회복, 관계 인물의 중재 또는 추가 증거가 필요하다.

## 7. 관계 인물 구조

- 1차 본편은 우호·중립 5종족에 대응하는 표준 관계 인물 5명을 기준으로 한다.
- 관계 인물은 호텔 소속이 아니라 외부에 자기 생활과 공동체를 가진 손님으로 처음 등장한다.
- 진행 단계는 `첫 방문 손님 → 단골 손님 → 종족 연락책 → 조사·운영 협력 NPC → 선택적 상주 동반자`를 기준으로 한다. 모든 인물이 마지막 단계까지 가거나 호텔에 거주할 필요는 없다.
- 협력 NPC가 되어도 일상 접객 직원으로 배치하지 않는다. 중립 오토마타가 접객을 담당하고, 관계 인물은 종족 정보·협약·시설·사건 대응·조사·전시품 후보와 특수 선택지를 제공한다.
- 조사 신뢰는 여러 관계 인물과 동시에 높일 수 있고 종족 사건·공동 조사 지원에 사용한다.
- 개인 호감도는 제한된 자유시간과 장면 선택을 사용한다.
- 일반·종족 경로에서는 모든 관계 인물의 개인 관계를 한 런에서 완성하지 못하게 한다. 트루 분기의 추가 영업·사건·자유시간을 정확히 사용한 경우에만 전원 조건 완성이 가능하다.
- 관계 인물에게 N/R/SR/SSR 등급을 붙이지 않고 일반 손님 시장·금액·평판 계산과 분리한다.
- 핵심 보상은 감정적 장면, 관점, 사건 선택과 엔딩이다. 조사 신뢰와 개인 호감도의 일정 기준에서는 서로 다른 전시품 후보군과 최초 기념 제안을 열지만, 선택한 패시브는 현재 런에만 남고 연애 후보가 실무 협력 후보의 상위 호환이 되지 않는다.
- 각 우호·중립 종족도 우호도와 관련 사건 기준을 만족하면 종족 전시품 후보군과 최초 기념 제안을 연다. 반복 평판 수치만으로 지급하지 않는다.

## 8. 상속 부채, 호텔 재가동과 엔딩

- 플레이어에게 보이는 기본 승리 축은 일정 영업 안에 상속 부채를 상환해 호텔을 지키는 것이다.
- 새 캠페인은 첫 영업과 최소한의 재가동 선택을 수행할 수 있는 일부 운전자금을 지급한다. 정확한 시작 금액은 `56/70일` `PROVISIONAL` 달력의 수요 곡선·일일 유지비와 함께 시뮬레이션한 뒤 확정한다.
- 초반의 객실·시설 선택은 신축 공사가 아니라 선대부터 존재하던 비활성 구역의 재가동이다. 선택한 구역은 오토마타가 하루 동안 정비해 다음 날부터 사용할 수 있다.
- 활성 객실·시설 규모에 따라 오토마타 유지비를 매일 자동 차감한다. 재가동으로 수용력과 수입 상한을 넓히는 선택은 당일 비용뿐 아니라 남은 기간의 고정비를 함께 늘린다.
- 재가동 전에는 다음 날 늘어나는 수용력·효과와 일일 유지비 변화를 공개한다. 사용하지 않는 구역의 유지비를 활성 구역과 동일하게 청구하지 않는다.
- 투자·재가동·일일 유지비와 최종 부채 상환 사이의 교환 관계를 유지한다.
- 각 챕터 결산에서 누적 상환액이 해당 챕터의 최소 의무액 이상인지 검사한다. 챕터 1은 첫 소액 상환, 챕터 5는 day 56 전액 상환이며 정확한 중간 금액·비율은 `PROVISIONAL · TBD`다.
- 매 영업 정산에서 최소 의무액을 넘는 추가 상환을 선택할 수 있다. 추가 상환은 부채 원금을 줄이는 대신 재가동과 유지비에 쓸 유동 자금을 줄인다.
- 챕터 마지막 날의 정산 순서는 `당일 수입·유지비 확정 → 선택적 추가 상환 → 누적 최소액 검사`다. 직전 영업을 다시 하면 확정 전 상환 선택도 체크포인트와 함께 롤백한다.
- 안정 운영은 메인 스토리를 완주할 수 있지만 확인할 수 있는 관계와 진상은 제한된다.
- 종족·관계 엔딩도 기본 운영 목표를 달성한 경우에만 열린다.
- 본편 56일과 트루 분기 70일의 종단 경계는 `PROVISIONAL` 기준으로 사용한다. 부채 원금·챕터별 누적 최소액과 비율, 재가동 비용과 활성 규모별 유지비는 별도 시뮬레이션한다.
- day 56에 부채를 전액 상환한 런만 트루 조건을 검사해 숨은 챕터 6에 진입한다. 추가 14일은 상환 유예가 아니며 미상환 부채를 이월하지 않는다.
- 현재 5영업 GREYBOX의 수입은 하루 수입 규모 참고치일 뿐 시작 운전자금·부채 원금·챕터별 누적 최소액이나 `56/70일` 안의 상환 가능성을 단독으로 입증하는 근거가 아니다.

### 현재 경제 시뮬레이터 구현과 검증 경계 — IMPLEMENTED

기능 커밋 `564c204`에서 경제 분석기를 실제 캠페인 재무 전이와 같은 순서로 교체했다. 세 비교 전략은 챕터 부족분을 자동 인출하거나 현금만큼 부분 납입하는 별도 게임 규칙이 아니라, 가용 현금과 남은 부채 안에서 하나의 명시적 `manualRepayment`를 고르는 정책 에이전트다. 분석기는 `stageNumber`, 두 결과 식별자, 수입, 유지비, 재가동비와 객실 정비비의 일곱 키를 커밋하고 `{ "manualRepayment": 금액 }` 하나만 정산해 실제 `commit → 명시적 상환 → 체크포인트`를 통과한다.

재가동비와 객실 정비비는 영업 전에 `liveCash`에서 먼저 지불한 준비비로 추적한다. 준비비를 낼 수 없으면 영업 전에 거부하고, 운영 현금 부족·챕터 허들 미달·day 56 부채 미상환이 확정되면 즉시 종단해 이후 날짜의 가상 수입을 합산하지 않는다. day 56의 부채 해결 증거가 있을 때만 57일을 열며, 숨은 챕터에서는 부채와 상환액을 0으로 유지한다. 보고서 스키마 v2는 조기 종료까지 실제 실행한 구간인 `executed_prefix_*`와 실제 관측한 day 56 결산을 분리한다.

공통 fixture에서 실제 `src/campaign-finance.js`를 부르는 JavaScript oracle과 독립 Python 미러를 비교한 결과, 18개 사례의 수락 12개·거부 6개, 원장 278행·추적 이벤트 851개가 일치했다. 엄격 로더 2개, 상태 검증 5개, 공개 API 형태 4개 probe도 `PASS`했다. 이는 이미 결정되고 선지급 가능한 하루별 재무 입력의 전이 정합성만 입증한다. 손님 생성·배치·점수·공사 자격·객실 적합성과 전체 `GameController` 경로는 범위 밖이고, 어떤 시작 자금·부채·허들·비용 수치도 밸런스 `PASS`로 판정하지 않는다. fixture와 분석기 수치는 모두 `PROVISIONAL · NOT_EVALUATED`다.

### 엔딩 판정 계층

엔딩 후보는 동시에 여러 개가 성립할 수 있으므로 아래 순서에서 가장 구체적인 하나를 채택한다. 배드 엔딩 조건은 다른 모든 후보보다 먼저 운영 생존 여부를 검사한다.

본편 56일 경계에서는 먼저 상속 부채 전액 상환을 검사한다. 미상환이면 배드 엔딩이며, 해결한 런에서만 일반·종족·관계 결말 후보와 트루 분기 진입 자격을 판정한다. 트루 자격까지 충족한 런만 57~70일의 숨은 챕터 6으로 이어지고, 추가 계절이 끝난 뒤 트루 계층을 최종 판정한다. 이 날짜는 `PROVISIONAL` 제작 기준이다.

| 우선 | 계층 | 정식 설계 기준 조건 · 부채 경제 교체 후 |
| ---: | --- | --- |
| 1 | 배드 | CH1~4 누적 최소 상환 허들 미달 또는 day 56의 상속 부채 미상환 |
| 2 | 트루 하렘 | 트루 조건과 5명 전원의 관계 엔딩 조건 완료 |
| 3 | 트루 | 악신의 증거와 전 종족 평화 협약 완료. 조건을 채운 관계 인물 중 한 명을 선택하거나 단독 결말 가능 |
| 4 | 종족 관계 인물 | 최고 우호도 종족의 전용 협약과 해당 관계 인물의 필수 사건 완료 |
| 5 | 종족 | 최고 우호도 종족이 임계치를 넘고 해당 종족 결말 협약 발동. 몽마는 타종족 우호 교류망도 필요 |
| 6 | 노말 | 호텔 생존 목표를 달성했지만 상위 분기 미충족 |

종족 우호도 동률은 자동으로 낮은 순번 종족을 고르지 않는다. 마지막 운영 방향 선언이 최고 우호도 집단 중 하나를 확정했을 때만 종족 엔딩으로 가며, 선언이나 전용 협약이 없으면 노말 엔딩으로 귀결한다.

CH1~4의 누적 최소 상환액을 미달하면 해당 챕터 결산에서 즉시 배드 엔딩으로 닫고, day 56 전액 상환 실패도 같은 운영 실패 계층으로 판정한다. 매 영업 정산에서 상환액을 선택할 수 있으므로 같은 결정을 반복하는 회복 전용 영업은 두지 않는다. 대신 다음 허들의 목표·현재 누적액·부족액·남은 영업일·일평균 필요 상환액을 사전에 표시한다. 챕터별 최소액과 비율은 이후 경제 시뮬레이션에서 확정한다.

### 종족 엔딩에서 지배인의 종족 선택

플레이어는 인간 지배인으로 캠페인을 시작한다. 종족 엔딩의 후일담에서는 인간으로 남는 선택과 해당 종족의 삶에 들어가는 선택을 열 수 있으며, 캠페인 중간에 종족을 바꾸어 객실 규칙이나 운영 능력치를 얻는 성장 시스템으로 사용하지 않는다.

| 종족 | 지배인의 엔딩 선택 |
| --- | --- |
| 인족 | 인간 지배인으로 남아 두 세계의 중재자가 됨 |
| 뱀파이어 | 인간 유지 또는 합의된 전환으로 뱀파이어가 됨 |
| 늑대인간 | 인간 유지 또는 합의된 물림·의식으로 늑대인간이 됨 |
| 마녀 | 인간인 채 약초학·마법 전수 또는 마녀 각성. 여성 지배인은 현재 성별로 각성하고 남성 지배인은 여성의 몸으로 바뀐 뒤 각성 |
| 몽마 | 인간 유지 또는 특별한 의식을 통한 사후·미래의 몽마 전생 |

몽마는 동족끼리 정기를 순환시키는 것만으로 장기 생존할 수 없으므로 `몽마 최고 우호도`만으로 종족 엔딩을 열지 않는다. 타종족 중 일정 수가 별도 우호도 기준을 넘고 합의된 꿈·정기 교류망이 성립해야 한다. 회색 상자에서는 `타종족 우호도 3 이상인 종족 2개`를 임시 기준으로 검증하며, 숫자는 정식 경로 시뮬레이션 뒤 교체한다.

### 관계 인물 후일담

- 모든 엔딩에서 실제로 만났거나 개인 장면을 연 관계 인물만 후일담에 등장한다. 만나지 않은 인물과 숨은 인물의 존재를 누설하지 않는다.
- 호텔 실패가 모든 인물의 삶을 붕괴시키지는 않는다. 독립적인 손님은 자기 삶으로 돌아가고, 호텔과 추진하던 협약·조사·거처에 실제로 의존한 부분만 영향을 받는다.
- 개인 사건에서 이미 얻은 성장은 배드 엔딩이라는 이유로 소급 취소하지 않는다. 미해결 문제는 해당 인물 사건의 인과에 따라 남는다.
- 관계 인물 엔딩은 해당 인물이 자기 종족과 삶을 버리고 직원이 되는 결말로 고정하지 않는다. 종족 대표, 외부 협력자, 공동 운영자 또는 동반자로서 호텔을 오갈 수 있다.

## 9. 무한 영업

플레이어 노출 명칭은 `무한 영업`으로 사용한다. `데스매치`는 내부 설계 설명에만 사용할 수 있다.

### 시즌 루프

1. 시즌 시작 시 영업 횟수와 다음 감사 목표를 공개한다.
2. 시드 기반 손님을 수용·거절하고 객실을 배정한다.
3. 영업 사이 시설·아이템·증축·계약 중 제한된 선택을 한다.
4. 시즌 종료 시 최근 운영 성과로 감사 평판을 계산한다.
5. 목표 이상이면 다음 위험 단계와 보상 풀을 연다.
6. 목표 미달이면 호텔 폐업으로 런을 종료하고 기록을 남긴다.

초기 5영업 표본은 종단 검증을 통과했으나 정식 시즌 길이로 확정하지 않는다.

### 현재 개발본의 회색 상자 계약 — GREYBOX · PROVISIONAL · SPINE PASS

`?mode=endless`에는 시즌 브리핑, 공용 전시품 제안, 영업 누적, 감사, 다음 시즌과 폐업 기록의 상태 경로를 연결했다. 이는 구조 검증을 위한 개발본이며 정식 시즌 길이·난도·보상 규칙이 아니다.

- 한 시즌은 임시로 5영업이다.
- 감사 목표는 통과 시즌 수에 따라 `0 → 2 → 4`로 오르고 이후 4에서 임시 상한을 둔다.
- 감사 점수는 해당 시즌 평판 변화 합계에서 마감 긴급 처리 1회당 1점을 뺀다.
- 남은 영업 1회당 최대 +4를 얻는다고 가정한 예상 상한으로 현재 목표의 도달 가능성을 표시한다.
- 시즌 통과마다 런 명성은 임시로 +1, 위험 단계는 `T1`에서 시작해 임시로 +1 상승한다.
- 런 명성과 위험 단계는 현재 화면·저장·기록 계약을 검증하기 위한 값이며 손님·시설·아이템·계약 풀을 실제로 확장하는 정식 밸런스는 아직 연결하지 않는다.
- 목표 미달은 폐업 종료와 실행 기록으로 이어지고, 통과하면 다음 시즌 브리핑과 새 전시품 제안으로 이어진다.
- 위 수치로 시즌 통과·다음 시즌·감사 미달·폐업, 저장·직접 재시도·1280×720 회귀를 실제 Edge에서 검증했다. 40시즌·200영업 장기 합성 런도 최근 영업 결과 20개·감사 12개 상한과 별도 누적 집계를 유지했다.
- Electron 파일 회귀에서는 5영업 감사 실패로 무한 영업을 종결해 `.endless` 활성 파일만 tombstone으로 닫고, 캠페인 활성 파일의 주·백업 바이트와 재개 상태가 그대로 남는 것을 확인했다.

### 두 평판

- `런 명성`: 전체 런에 누적되며 손님·시설·아이템·계약 풀을 확장한다.
- `감사 평판`: 최근 시즌의 만족, 거절, 취소와 사고를 계산해 생존을 판정한다.

누적 명성만으로 생존을 판정하지 않는다. 초반 성공을 무기한 비축하거나 초반 실패가 영구 회복 불가능해지는 것을 막기 위해 감사 평판은 시즌마다 초기화하거나 제한적으로만 이월한다.

감사 목표는 시즌 시작 전에 공개하고 현재 속도로 도달 가능한지 표시한다. 종료는 가혹할 수 있지만 숨은 기준이나 사후 변경으로 발생해서는 안 된다.

## 10. 모드 간 상태 경계

두 모드는 운영 수첩 프로필을 공유하며, 여기에는 전시품의 후보군 자격과 제안·획득·발동 도감이 포함된다.

Electron 파일 저장에서도 이 경계를 그대로 사용한다. 프로필·운영 수첩과 최근 실행 기록은 공용 파일이고, `SHOWCASE`, `CAMPAIGN`, `ENDLESS`의 활성 런은 각각 별도 주·백업 파일이다. 캠페인은 저장 재개 직후 `completeRun()`으로 명시적 `CAMPAIGN_INTERRUPTED` 중단 엔딩을 확정했으며 이는 5영업 완주 검증이 아니다. 무한 영업은 실제 5-operation 감사 실패로 종결했다. 두 경우 모두 대상 파일만 tombstone으로 닫고 비대상 파일 바이트를 보존했으며, 프로세스 재시작 뒤 비대상 모드가 같은 시드·단계로 재개됐다.

시드는 각기 다른 가능 세계를 가리킨다. 캠페인 세이브는 지배인과 호텔의 한 세계선을 보존하고, 무한 영업 시드는 별도 런을 만든다. 현실과 예지의 세계관적 해석은 시나리오 캠페인의 비서 장면에만 적용한다. 무한 영업의 `이번 영업 다시`는 체크포인트를 복원하는 기능적 편의이며 서사 사건이나 설정 단서로 취급하지 않는다. 캠페인의 장기 복귀점은 챕터 시작 하나, 단기 복귀점은 현재 영업 시작 하나로 제한하며 챕터 내부 여러 영업을 임의로 골라 되돌리지 않는다.

### 공유

- 확인한 호텔 규정과 종족·직업 정보
- 시설·아이템의 존재와 효과
- 발견한 숨은 선호와 시너지 변화형
- 손님 조우·투숙 기록
- 업적, 장식, 칭호와 최고 기록
- 전시품 후보군 자격과 제안·획득·발동 기록

### 분리

- 골드와 호텔·종족 평판
- 실제 소유 시설·아이템, 현재 런의 전시품 조합과 증축 상태
- 종족 협약과 현재 시너지 변화형
- 관계 인물 조사 신뢰·개인 호감도와 선택한 성별 변형
- 시나리오 플래그, 조사 증거와 엔딩 상태

캠페인에서 해금한 종족·시설 변형은 무한 영업의 생성 풀을 확장할 수 있다. 무한 영업에서 발견한 일반 손님 선호와 시설 사용 기록은 캠페인 수첩에서도 열람할 수 있다. 전시품 후보군 자격은 무한 영업의 제안 풀을 넓힐 수 있지만 이전 런의 실제 전시품과 패시브를 가져오지는 않는다. 새 런은 열린 풀에서 다시 무작위 후보를 선택한다.

- 선지자의 후손 가문이 예지안을 지닌 후계자가 태어나 능력을 각성할 때까지 베스페라와 오토마타를 유지해 왔다는 진실은 히든 조사 경로에서만 밝힌다. 상속 부채라는 표면 목표와 일반 캠페인 UI에서는 이 배경을 해설하지 않는다.
- 기본 캠페인 생성기는 숨은 조사 분기 전까지 도플갱어 예약을 만들지 않는다.
- 숨은 조사 진입은 우호·중립 5종족의 신뢰, 핵심 사건 해결, 연합 신뢰, 각 종족의 증거 조각, 모든 관계 인물의 조사 협력과 호텔 생존을 함께 요구한다.
- 모든 관계 인물의 개인 호감도나 로맨스 완성을 요구하지 않는다.
- 화합 선택은 연합 신뢰와 증거 확보 비용을 낮추지만 중반 운영 난도를 높인다.
- 전문화 선택이 있어도 진입은 가능하되 늦은 화해·재건·추가 조사 비용을 요구한다.
- 숨은 조사 챕터는 예약 원본 비교, 단서와 보안 시설을 학습시킨다.
- 숨은 결전 챕터는 전 종족 시설·상극·시너지, 침투 위험과 대규모 평판 공격을 결합한다.
- 숨은 분기 해금은 한 번 성립하면 유지한다. 이후 평판 손실은 성공을 어렵게 하지만 이미 발견한 정체를 다시 숨기지 않는다.
- 관련 운영 수첩 항목은 발견 전에는 빈 슬롯, 총개수와 미발견 힌트도 표시하지 않는다.

## 12. 공정성과 검증 조건

- 경로별 추가 영업이 누적 평판과 골드를 자동으로 유리하게 만들지 않아야 한다.
- 종족 평판과 연합 조건은 개별 최대치가 아니라 전체 경로 시뮬레이션으로 검산한다.
- 종족 특수 영업은 대화만 있는 가짜 스테이지가 아니며 실제 운영 규칙을 가르치거나 시험한다.
- 사건 장면은 영업 제한 시간 중 강제로 재생하지 않는다.
- 선택 전에 시설·시너지·하드 제약의 운영 방향을 보여주되 숨은 엔딩 점수는 노출하지 않는다.
- 기본 엔딩, 관계 엔딩과 최고난도 경로가 각각 독립적으로 완결되어야 한다.
- 무한 영업의 감사 목표는 해당 시즌 상태에서 수학적으로 도달 가능해야 한다.

## 13. 다음 결정

실제 런타임과 같은 영업·지출·상환·실패 순서를 소비하는 경제 시뮬레이터와 JavaScript/Python 재무 전이 정합성은 완료했다. 사용자 결정 없이 이어갈 다음 P0는 이 검증된 전이 위에서 시작 자금·부채·챕터 허들·재가동비·유지비의 도달 가능 후보 범위와 민감도를 생성하는 일이다. 정확한 수치는 후보를 비교한 뒤 사용자가 결정한다. 정식 종족 방향·특화 시설·시너지 변화형의 첫 구체 조합도 사용자 결정을 기다리며 임의로 고정하지 않는다.

1. 공통 캠페인 대표 8~10영업과 종족 특수 영업 1세트의 실제 시간 측정
2. 종족당 세 사건 영업이 필요한지 표본 제작으로 검증
3. 전문화 뒤 화해 비용과 연합 신뢰 계산 방식
4. 관계 인물 조사 신뢰·개인 호감도 장면 수와 자유시간 슬롯 수
5. 성별 변형별 이름·초상·호칭·대사와 회상 기록의 제작 범위
6. 본편 56일·트루 분기 70일과 계절당 14일의 콘텐츠 밀도·경제 타당성 검증
7. 공휴일·특별 행사일의 명칭·배치·수요 변형 수치 확정
8. 시작 운전자금, 상속 부채 원금·챕터별 누적 최소 상환액·비율, 재가동 비용과 활성 규모별 일일 오토마타 유지비의 후보 범위·민감도 생성 후 사용자 확정
9. 무한 영업 회색 상자 검증 뒤 정식 시즌 길이, 감사 평판 공식, 런 명성·위험 단계와 난도 곡선 확정
10. 캠페인 해금이 무한 영업 생성 풀에 들어가는 정확한 범위
